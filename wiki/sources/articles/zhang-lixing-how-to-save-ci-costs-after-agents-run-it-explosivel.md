# 张立行 · Agent 把 CI 跑爆之后怎么省

*Zhang Lixing · How to Save CI Costs After Agents Run It Explosively*

帖文称，Agent 频繁运行 CI 会推高成本，优化应从测量开始：取消被新 push 取代的 PR 运行、Draft 阶段少跑完整 CI、只跑受变更影响的 job/测试，并用 merge queue 替代“必须 up-to-date with main”。同时应清理 Agent 容易生成的噪声测试并给测试代码设预算；缓存、并行分片和更快工具值得优化，加硬件一般是最后手段，24 小时高频开发时自托管 runner 成本显著更低。[^145b9cc6f526817d]

The post says that Agents frequently running CI drive up costs, and optimization should start with measurement: cancel PR runs superseded by new pushes, run less full CI in Draft stage, only run jobs/tests affected by changes, and replace “must be up-to-date with main” with a merge queue. Teams should also clean up noise tests easily generated by Agents and set a budget for test code growth; caching, parallel sharding, and faster tools are worth optimizing, adding hardware is generally a last resort, and self-hosted runners cost significantly less when Agents develop at high frequency around the clock.[^145b9cc6f526817d]
