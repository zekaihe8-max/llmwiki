# 选 Harness 不再比功能多，而是看能否持续改进工作流

*Choosing Harness: No Longer Comparing Feature Counts, But Whether It Supports Continuous Workflow Improvement*

「帖文称」小墨同学在使用 Pi Agent 和 DeepSeek Harness 期间，关注点从模型强弱和功能多寡，转移到工具能否适配并持续改进自己的工作流。他指出 DeepSeek Harness 桌面端便捷、新手友好，但自己更倾向 Pi，原因包括对工具加载、上下文压缩和任务执行的可控性、丰富的 Extension 插件生态，以及模型切换时 Skills、配置和工作流的长期复用。他也提到 Pi 插件过多会增加维护成本和兼容性风险，并认为模型更新很快，换模型不应重新折腾整个 Agent，选工具应看能否持续改进工作流。[^xiaomovps-harness-workflow]

In the post, Xiaomov says his focus has shifted from model strength and feature count to whether a tool can adapt to and continuously improve his workflow. He notes DeepSeek Harness is desktop-friendly and beginner-friendly, but still leans toward Pi for controllability, extensible plugin ecosystem, and long-term reuse of skills, configs, and workflows across model switches. He also warns that too many Pi plugins raise maintenance and compatibility risks, and argues that since models change fast, switching models should not require rebuilding the entire Agent.[^xiaomovps-harness-workflow]
