# 铁锤人：帖文称按 AI Token 消耗考核程序员不可靠

*Tie Chui Ren: Post claims evaluating programmers by AI token consumption is unreliable*

「帖文称」，越来越多大厂拿每周烧了多少 token 考核程序员有没有用好 AI，Meta 有人搭过全员排行榜，Salesforce 还定过最低消费额。但 JetBrains 和卡内基梅隆大学查完 404 名工程师 5 周账单和代码提交后，直接把这套玩法拆穿了：同样一周交差不多数量的代码，烧得最狠的前 10% 和最省的后 10%，token 消耗差了 39 到 240 倍；只看同一个人，这周把 token 消耗翻倍，代码提交也只多约 10%。帖文进一步指出，烧得猛不代表写得快，很多时候是在卡壳返工，AI 每聊一轮都会把前面对话和代码重新发一遍，长对话会让消耗暴涨而吐出新内容不到总消耗的 1%；412 人问卷也显示，近九成技术岗都拿 AI 干写代码以外的活，如分析数据、查资料、摸清陌生代码和定方案，这些功夫压根不会多出一条代码提交。结论是，拿 token 消耗考绩效，比以前按代码行数发奖金还不靠谱，只记了花掉的成本，根本不记做成了什么。[^lxfater-ai-token-performance-myth]

「The post claims」more and more big tech companies evaluate whether programmers use AI well by weekly token consumption, with Meta even creating company-wide rankings and Salesforce setting minimum spending quotas. But after JetBrains and Carnegie Mellon University examined 404 engineers' five-week bills and code commits, they debunked this approach: for similar weekly code output, the top 10% heaviest token burners and the bottom 10% savers differed by 39 to 240 times in token consumption; for the same person, doubling weekly tokens increased code commits by only about 10%. The post further notes that burning heavily does not mean writing faster—often it is stuck rework, and AI resends previous conversations and code every round, so long conversations cause consumption to surge while new output is less than 1% of total consumption. A 412-person survey also shows nearly 90% of technical roles use AI for non-coding work such as data analysis, research, understanding unfamiliar code, and planning, none of which produces additional code commits. The conclusion: evaluating performance by token consumption is even less reliable than paying bonuses by lines of code, because it records cost but not output.[^lxfater-ai-token-performance-myth]
