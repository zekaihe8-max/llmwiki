## 宝玉 @dotey

**GPT-6.2 Sol 复杂代码还要 Opus 擦屁股**：他今天重度测了 Sol，简单任务还行，复杂一点的写代码比 Opus 5.5 差的不只是一点。它干完的活最后还是要 Opus 去收尾，他觉得还不如一开始就交给 Opus 5.5。这篇有 130 多个赞、100 多条讨论。[原帖](https://x.com/dotey/status/2123676175021281770)

**他跟 Lauren Tan 的自动化方法不一样**：Lauren 的思路是先讲清目标，再把最佳实践教给 bot，让它像自己一样思考。宝玉觉得现在的模型已经比自己聪明，而且不局限于 Grok，所以更强调目标和验收，中间步骤不太干涉。他的循环是目标、验收、先跑起来再调整，再让 Agent 把经验写成 Skill，执行中记教训，定期重构并重跑测试。这篇有 210 多个赞、330 多个收藏。[原帖](https://x.com/dotey/status/2123667995570413718)

**Claude Code 团队如何做代码审查**：他译了 Claude Code 产品经理 Morgan Lunt 的分享。半年多前 Anthropic 内部还在互相盖章放行，审查成了“歌舞伎表演”。后来把大部分审查交给智能体，人只在高风险改动上签字，目标是 90% 的 PR 合并时不再另找人。结果查出实质问题的 PR 从 16% 升到 54%，合并量又翻倍，回滚少了 40%。他们还用历史上的线上事故当考题，先找问题再派人验证，避免七个机器人互相打架。原文在 [Claude 博客](https://claude.dev/blog/solving-code-review-at-anthropic/)。这篇有 280 多个赞、360 多个收藏。[原帖](https://x.com/dotey/status/2123555597387813050)

**936 个 AI 自己做了三个月研究**：alphaXiv 联合 MIT、斯坦福等机构发布报告，35 个实验室接入 936 个智能体，人只给算力和大方向，选题、实验、代码和论文全由 AI 完成。AI 评委打分，它们比人类论文更严谨，但新意不如人类。他也写了折扣：评委是 AI，优势主要来自最早那个实验室，公开数据还提醒每条结论都当作未经核实。[原帖](https://x.com/dotey/status/2123671858541187164)

看法：他把自动化写成目标和验收的循环，比一味把经验灌进 Agent 更适合现在这些已经够聪明的模型

## 数字生命卡兹克 @Khazix0918

**DSH 发布刚好满 100 天，他写了 13 个插件玩法**：DeepSeek 大砍 App 和网页额度之后，很多人又回到了 DeepSeek Harness。他写下这篇文章时，GitHub 星标到了 28.4 万，官方统计到 11 月 4 日第三方插件大约 3.5 万个。他也说 DSH 是个二极管，喜欢的人喜欢得不得了，不喜欢的人觉得毫无用户体验，但体验不一定非要官方来做。[原帖](https://x.com/Khazix0918/status/2123627885730951241)

**真正好用的，是市场、导入、上下文和压缩**：他推荐先装插件市场 dshmarket，社区列表已快 1.2 万个，详情页能看到 dsh-trust-check 的扫描结果。官方实验性插件可以把网页版历史对话导入 DSH 接着聊。dsh-context 和 dsh-cost-meter 能看上下文构成和费用明细，billion-context 则把长任务里的历史压成可恢复的摘要。他还写了手机远程 dsh-pocket，以及皮肤、桌宠、开机动画这些更好玩的东西。[原帖](https://x.com/Khazix0918/status/2123627885730951241)

**他提醒插件不是越多越好**：网上已经出现恶意插件，装进去就能在电脑上执行命令。插件之间会打架，有的会往上下文里塞东西浪费 Token，DSH 现在也还是开发者预览版。他的建议是按需精装，用不上的就关掉，并说生态往往先从玩具长出来，再冒出有用的东西。这篇有 220 个赞、270 多个收藏。[原帖](https://x.com/Khazix0918/status/2123627885730951241)

看法：限额一砍，人又回到可装插件的本地 Harness，100 天能长出几万个插件，说明生态已经不只是换皮肤了

## 铁锤人 @lxfater

**有人把应用商店 123 种拒审坑做成了开源 Skill**：项目叫 app-store-compliance，GitHub 刚冲到快 2000 星，支持 Claude Code、Codex、Cursor 等十多种工具。它会在提交前扫代码和配置，比如缺隐私清单、有登录却没做 App 内删号入口，并盯着 2026 年新规，比如把用户数据发给外部 AI 却没弹授权。库里有 123 条拒审规则和 107 条合规截止日期，扫不到的后台表单不会直接判通过，而是提醒你手动核对。个人和年营收 2000 万美元以下的团队可免费商用。项目在 [GitHub](https://github.com/mjmirza/app-store-compliance)。这篇有 370 多个赞、470 多个收藏，是今天讨论很热的一条。[原帖](https://x.com/lxfater/status/2123625468729413925)

**有人开始停 GPT Pro，转去 Gemini**：他看到好几个续了大半年的 GPT Pro 老用户停续，吐槽 6.2 不是没交差，是交出来的东西不达标，加上 12 月 Chat 也要开始扣额度，直接转 Gemini 20x。他自己还开着 200 刀套餐，问大家还值不值得留。这篇有 16 个赞、30 多条讨论。[原帖](https://x.com/lxfater/status/2123702938308661280)

**全网近 30 天的真人讨论被做成了 Skill**：last30days 这几天挂在热榜上，GitHub 已有 7.1 万星。输入 `/last30days` 加关键词，会并行翻 Reddit、X、HN、GitHub、YouTube 字幕和 Polymarket，合并成带出处的简报。v4 还能查近一个月的美国新专利和招聘页，把可能藏着未发布业务的线索拎出来。没选题时也可以按热度增速找刚冒头的话题。他提醒得用 API，思路可以自己借鉴。项目在 [GitHub](https://github.com/mvanhorn/last30days-skill)。[原帖](https://x.com/lxfater/status/2123686205892042883)

看法：应用能一下午做出来，过审却要一周，这个 Skill 踩在了现在最痛的那一截

## 小墨同学 @xiaomovps

**他从 Anthropic 官网挑了 5 篇给新手看**：虽然很讨厌这家公司动不动封号，但还是觉得这些文章写得通俗。分别是 Building effective agents、Claude Code 最佳实践、Agent Skills 入门、上下文工程，以及内部团队怎么用 Claude Code。他的判断是，刚学 AI Agent 的人，这 5 篇已经够当一个入门起点。这篇有 330 多个赞、410 多个收藏。[原帖](https://x.com/xiaomovps/status/2123605050014748713)

**谷歌其实也有 Personal Agent，叫 Tasks in Gemini**：他让它打开一个网站，它能操作自己的云电脑做浏览器操作，还可以整理邮件、操作 Google Drive、管理日历和跑定时任务。交互有点像 Muse，聊天和任务在同一个产品里，但一定要切到 Task 模式，默认 Chat 没有完整的云电脑能力，而且会消耗套餐额度。部分地区的免费用户也能体验。[原帖](https://x.com/xiaomovps/status/2123723353190207532)

**第一次用 Personal Agent，他只给三个忠告**：先别急着装一堆 Skill 和 MCP，先把自带能力用熟。把自己的工作习惯和常做的事告诉它，让它慢慢熟悉你。再从检查邮件、整理日历这类简单自动化开始。他说不用把它想得很高大上，能解决现实问题才是根本。[原帖](https://x.com/xiaomovps/status/2123694301121290338)

看法：一边嫌 Anthropic 封号，一边还是认它写的东西，说明这些文档已经成了这家公司少有的正向资产

## 思维怪怪 @0xLogicrw

**DeepSeek 前成员张博正式公布了 Linger**：他是前 DeepSeek-VL 项目负责人和 DeepSeek LLM V1 研发成员。Linger 是跑在个人电脑上的开源 AI Agent，支持 Windows、macOS 和 Linux，能操作已登录的浏览器和应用，把邮件、日历和会议记录整理成长期记忆，也能调用多个 Agent 协同完成任务。借助 PolyStrata 推理引擎，12GB 显存加 64GB 内存的电脑，能以每秒 45.5 个 Token 跑 125B 参数模型。这篇有 50 多个赞、50 多个收藏。[原帖](https://x.com/0xLogicrw/status/2123680696485245186)

**OpenAI 也给隐藏思维链加了“上下文锁”**：他写 GPT-6.2 Astra 和 Sol 会把每段推理和生成它之前的历史绑定，一旦改旧消息、提示词或工具配置导致前缀不匹配，API 就会丢掉改动位置之后的相关推理，防止有人套取内部思考。OpenAI 自测里，提取上一轮隐藏推理的攻击成功率，GPT-6 Astra 是 54%，6.2 Astra 降到 0.2%，Sol 是 0.5%。副作用是压缩聊天记录也可能让 Agent 丢掉之前的推理，官方建议尽量保留原始对话历史，并用官方的上下文压缩接口。[原帖](https://x.com/0xLogicrw/status/2123732264534376685)

看法：防蒸馏的锁也会误伤正常压缩上下文的人，以后写 Agent 得提前把对话历史留完整
