## 数字生命卡兹克 @Khazix0918

**深度实测 GPT-6.2，说 OpenAI 在偏科的路上越走越远**：等了近 20 天，Astra 和 Sol 终于一起上了 ChatGPT、Codex 和 API。他的总评是有点失望，这个模型极其偏科，对自己很难有质的飞跃。价格上 Astra 降了 20%，每百万输入 8 美元、输出 40 美元，缓存从 1 美元降到 0.4 美元，跟降价后的 Fable 5.2 对齐，Sol 仍是 2/10、缓存 0.1 美元。他强调纸面单价没那么重要，真正拉开差距的是完成任务要烧多少 token：官方 Agents' Last Exam 上 Astra 大约 78 分、每任务约 3 美元，Fable 5.2 大约 73 分、约 60 美元，分数高 5.5、成本只有大约 5%。他自己用 200 刀 Pro 跑了 4 个视频和 3D、2 个大方案规划、近百个代码审查，只消耗 6% 周额度，上次 Fable 5.2 十个 Case 就烧了近 30%。[长文](https://x.com/Khazix0918/status/2122858329248825669)

**方案规划可读性差，代码审查却明显进步**：他拿 AIHOT 加留言区这个真需求做对比，Gemini 4 Carbon 五分钟给出合规要点和最小成本方案，可读性很强，Astra 跑了 24 分钟，回复又短又让人云里雾里，还建议前期人工审核。代码审查是他用 GPT 最多的场景，自建简易评测集上，GPT-6.1 Sol 只能找出 65% 的问题，6.2 Sol 到了 84%，Astra 直接到 96%，但 Astra 比 Sol 慢大约一倍、贵 4 倍，只多找出十几个 BUG，所以他准备默认用 Sol xhigh 做审查。[长文](https://x.com/Khazix0918/status/2122858329248825669) [原帖](https://x.com/Khazix0918/status/2122811072025694318)

**审美仍是短板，3D 反而超预期，他建议让 Claude 或 Gemini 去指挥 GPT**：视频老 Case 上他把 Fable 5.2、Carbon 和 Astra 放一起比，说除了 3D，其他跟 Claude 比就是一坨屎，OpenAI 至今不懂审美。但神庙逃亡、秋日火车站、古希腊世界这些 3D 和 Three.js 案例让他很惊喜，有的调一轮就很酷。最后他说很多人觉得 Claude 做 ToB、GPT 做 ToC，其实反了：Claude 和 Carbon 更适合普通人沟通和主动拓展，GPT 严谨听话、工业属性重，更适合科研和算法的人。他自己的解法是承认不够会指挥 GPT，让 Claude 或 Gemini 去管它。[长文](https://x.com/Khazix0918/status/2122858329248825669)

**把交互和文案交给 Gemini 4 Carbon 把关**：Claude 做方案规划和设计执行时，他会把交互设计和界面文案交给 Carbon 再看一眼，觉得用户体验会舒服不少。这篇有 260 多个赞、230 多个收藏。[原帖](https://x.com/Khazix0918/status/2122692392218464305)

看法：评测数字和他自己的手感对得上，GPT 继续往又便宜又严的方向走，要的如果是好沟通和好看起来，别指望这一代自己变了

## meng shao @shao__meng

**LangChain 谈主动式 Agent：超七成运行靠日程**：当 Agent 在后台推进持续数天、数周的目标，瓶颈不再是模型能不能干完，而是人有没有时间处理它不断送来的问题和结果。内部销售 Agent 和工程 Agent Robin 里，超过 70% 的运行由日程触发，不是人临时输入。他们把主动拆成两件事：没有新提示时仍能继续工作，以及少占用人的注意力，记忆和评审界面是后半段的关键。[原帖](https://x.com/shao__meng/status/2122995228689010872)

**Devin Bots：交给它的不是工单，是一项职责**：和一次请求一次执行的 Devin 会话不同，Bot 持续存在，能拆目标、拉多个会话并行，再跟进测试和审查。官方例子里，Android Bot 在没有专职 Android 工程师的情况下用 44 天做出应用，合并 1134 个 PR、关闭 1217 张工单、写了约 34.5 万行 Kotlin，负责人只发了 183 条消息，其中 22 天完全没说话。Layout Bot 三周合并 159 个相关 PR，团队称卡顿降低 70%。内测用户平均每条消息对应的已合并 PR 数量达到此前的 4.5 倍。他也提醒，PR 数量并不直接等于软件价值。[原帖](https://x.com/shao__meng/status/2122992266637955157)

**Chrome 案例：Policybazaar 把前端验证从 4 天缩到数小时**：用 Modern Web Guidance 约束写法，再用 Chrome DevTools for agents 检查真实页面。性能审计工作量下降约 92%，关联品牌 Pensionbazaar 新页面从代码到完成验证由约四天缩至数小时，因界面与设计不符提出的 UI 缺陷减少 90% 以上。他特别写了，这些数字衡量的是验证效率，不是线上核心指标也提升了同样比例。[原帖](https://x.com/shao__meng/status/2122983021129425047)

看法：三篇都在讲同一件事，模型会写只是起点，谁来验收、谁来记得上次的反馈，才决定能不能长期用

## 小墨同学 @xiaomovps

**有人为 Pi 专门训了一个模型 Qwen3.8-27B-pi-adapted**：在原版 Qwen 上用强化学习和 LoRA 做适配，思路不是再加插件或改提示词，而是让模型熟悉 Pi 的工具和习惯。项目方称 SWE-bench Pro 通过率从 29.4% 提到 62.7%，工具调用次数减少 55% 到 62%，权重已公开，可尝试本地部署，他也说这是特定测试环境里的结果。[原帖](https://x.com/xiaomovps/status/2122997925446127660)

**自媒体工作台补上了信息获取和多平台分发**：前面那套 3 个插件还缺两块，他找了 OpenBiliClaw 从 X、B 站、小红书、抖音、YouTube 收热点，已支持 DeepSeek Harness 插件；social-auto-upload 能向多个平台自动传视频，但不是原生插件，涉及登录和风控，他建议先拿小号测，别直接用主号。[原帖](https://x.com/xiaomovps/status/2122981656198074383)

**Claude Code 的 Code Mode 和 Pi 的 Codemode 殊途同归**：都是让 Agent 用 JavaScript 一次串多个工具调用，只把有用结果交给模型。Pi 可用 `pi --tools +codemode` 临时体验，有 on 和 only 两种模式，他建议新手先用 on。他也提醒 QuickJS 只隔离脚本，删文件、改数据库仍要做好权限控制。[原帖](https://x.com/xiaomovps/status/2122964434276786268)

看法：补工作流的人比再吹一个新模型更实在，不过自动分发这件事，风控是真风险，别拿主号去试
