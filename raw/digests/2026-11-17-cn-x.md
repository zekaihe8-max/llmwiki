## 数字生命卡兹克 @Khazix0918

**时隔 3 年，重新入职淘宝当了一天设计师**：他以前做了十年用户体验设计，2023 年起改做 AI 博主。半个月前忽然想知道老本行到底变成什么样了，淘宝设计帮他协调了一天，双十一前拿到工牌，真的上班干活。[长文](https://x.com/Khazix0918/status/2122570393836019933)

**团队在 AI 上分三块，吃饭家伙是自己搓的 TaoDesign**：一块是创意，淘天每天大量会场和投放物料，已基本交给「淘天 AI 设计师」，创意同学更多是提需求、编排 Agent、调风格。一块是知识，界面、体验、营销和设计系统一共 200 多个知识库已经洗进 AI，新人不用再满世界问规范归谁管。最核心的是内部工具 TaoDesign，他们先做过对话式生成 HTML，再做成 Figma 和 MasterGo 插件，都觉得不对，希望交付物直接就是上线的产品，不再有实现漏损。大约半年前决定自己造工具，因为它把 AI 和画布绑在一起，还能接上淘宝十几年的规范和业务知识。唤起输入框后，顶上会弹出灵动岛看进度，选手淘模板、扔进 Prompt 或 PRD，就能生成可点、可滑、带动效、并且符合规范的稿。换图改字能直接调用真实业务资源，他随手把详情页全部换成 iPhone Duo，价格和文案核对后都是对的。风格库把存量设计稿、组件 Token、效果好的历史 PRD 蒸馏成 Skill，规范迭代要二次蒸馏、左右对比，最后仍由人确认。用研还搭了数字用户库，一对一或六人圆桌出报告大约 15 到 20 分钟，急的话还有两分钟的调研快问，另有一个页面数据预测 Skill，能估识别度和可能被点的位置。[长文](https://x.com/Khazix0918/status/2122570393836019933)

**下午 2 点半接需求，5 点评审，他先把许愿式编程翻了个车**：双十一结束后要做冬季促销上新，首页行业频道加入口，点进去是独立承接页，购前到购后全链路都要打上冬促标，商家后台也要做，最好交出可点的交互 demo。运动户外给丘黎，家居给阿诏，他分到服饰。以前这类活接近一周，主管承一觉得不难，定了 5 点评审。他习惯把大任务一次性丢给 Claude Code，于是把聚合页、店铺、详情、购物车、订单一口气全扔进去，还并行开了好几个会话。师姐七禧劝他一个一个来，他没听。一个多小时后跑出 8 个页面，规范没守，冬促标签也是错的。原因是 TaoDesign 里 Prompt 优先级高于模板和知识库，新人写一堆自以为是的细节，就会把十几年规范盖掉。后来他 Prompt 写粗一点，先只做店铺页再往下扩，同一对话会带着前面调好的规范，也可以引用别的会话，口喷改细节最快 43 秒就能看到结果。[长文](https://x.com/Khazix0918/status/2122570393836019933)

**评审和访谈把他从画图仔拉回设计师**：丘黎两个多小时就交出可点 demo，还有领券浮层、深色模式、缺省态、商家配置，并拉数字用户开圆桌，连 iPhone Duo 折叠屏都能真的折起来。他自己做了 3D 小 IP 打开冬季衣柜，下面用排行榜，标签改成蓝色，店铺页会下雪，讲完觉得羞耻。承一指出淘宝已有服饰榜单，目的性强的人会直接搜索，榜单又是效率型结构，用户看完前三后面基本不看，主视觉还占了首屏一半以上，对讲究屏效的淘宝并不合适。家居的阿诏从 GMV 和购买意图两边拆，意图不清的用直播和风格化榜单接住，意图明确的走最短下单链路。承一总结，执行和出方案 AI 已经够强，设计师反而要站得更高去思辨。晚上他问大 BOSS 奇维，AI 是不是只是让人更忙，奇维说以前有很多遗憾，没时间了解用户，现在那些被迫做的事 AI 接走了，「以前我有遗憾，现在我没有遗憾。」奇维认为核心能力是描述和判断，承一说会被替代的是只会机械执行的人，有观点、有判断的人会被放大。他们今年的方向是从交付设计，转为交付设计的能力，TaoDesign 大约 15% 用户已是产品经理。技术负责人骊仁有一句他记下了：TaoDesign 不是产品设计的终点，它是整个需求交付的起点。[长文](https://x.com/Khazix0918/status/2122570393836019933)

看法：最值钱的不是灵动岛有多漂亮，而是那句「Prompt 写细了反而会把规范盖掉」，以及空出来的时间必须回到用户和业务上，不然只是更快地画出一坨屎

## Barret李靖 @Barret_China

**AI 时代的儿童教育，他在问十六年到底学到了啥**：孩子幼儿园（他们家还上了小小班）四年，小学六年，初高中再六年，前前后后十六年。他反问，如果五岁开始持续学计算机或金融十年，十四五岁有没有机会在某些专业上接近专家水平。背古诗这类事门槛没那么高，逻辑、理解和表达变强之后，再去读诗并不特别难。他更想加强的是元认知：如何学习、如何思考、如何提问、如何判断自己的认知有没有偏差，再通过实践修正。[原帖](https://x.com/Barret_China/status/2122557084567032268)

**知识越来越好拿，学校时间却未必该那么长**：每个时代对人才的需求不同，教育一直在改。AI 让知识获取更容易，也更有机会按每个孩子的理解力、兴趣和进度做辅导，该重新想哪些知识需要花十几年反复学，哪些能力该从小练。他提到一则山区孩子接受较新 AI 教育的新闻，觉得资源原来更匮乏、既有体系约束更少的地方，反而可能先把新理念带进去；大城市体系成熟，理念往往更难改。学校当然有社交、合作和规则意识的价值，但这些是否要占掉十几年的大部分时间，他还在想。如果基础能用更短时间掌握，剩下的时间留给项目、运动、艺术和社会实践，孩子会不会反而长得更好。这篇有 170 多个赞、120 多个收藏。[原帖](https://x.com/Barret_China/status/2122557084567032268)

看法：问题问得很狠，答案还在探索，但这比再加一门 AI 课更值得想

## meng shao @shao__meng

**已经有 Claude Code 和 Codex 了，企业为什么还要招 Harness Engineer**：Reddit 上有个热帖，问自建是不是在重复造轮子。他把 harness 说成让模型持续工作的配套系统：管上下文、提供并执行工具、保存状态、处理失败和重试，并决定何时停止、何时要人批准。Claude Code 本身已包含面向编程的运行框架，并不是裸模型。有人问把规范写进 CLAUDE.md 不就够了，高赞回应点出关键区别：告诉模型应该怎么做，和由系统限制它只能怎么做，不是一回事。生产操作前必须审批、费用预算、数据范围和审计，都不能只靠模型记住要求。他自己的结论是先分清两个问题，模型有没有能力完成任务，系统能不能让它在规定条件下可靠完成；能靠配置、扩展工具和接入内部流程解决，就不必重写整套框架。[原帖](https://x.com/shao__meng/status/2122492485872308640)

**Together 用 Agent 测自家产品，失败的往往不是模型**：他们把真实需求写成任务，比如查 GPU 集群可用区域、找最便宜机型再生成预订命令，但禁止真下单，再比较只给提示词、接入文档 MCP、以及提供 Skills 三种配置。早期一项任务里，Sonnet 4.6 加 Skills 15 次只成功 4 次，Opus 4.8 则是 14 次里 13 次，原因不全在模型：Agent 把命令行示例当成实时库存，Skill 又把它带到营销页而不是价格表。补了两句，明确指向实时区域接口和价格表后，该任务在 Skills 配置下对所测模型全部通过。他们还把 14 个分散 Skill 合并成统一入口，第一次结果退步，72 次只通过 54 次，费用翻倍；压缩说明、更新过时模型并修好示例后，通过 70 次，约 97.2%，耗时下降约 20%，费用回到原来水平。[原帖](https://x.com/shao__meng/status/2122486376981795286)

**微软研究院开源 TokenEconomizer，不改模型，从仓库经验里省 token**：这是套外部控制器，读历史会话，再通过已有接口起作用：把微技能写入起始上下文、裁掉长期不用的工具，卡住时再干预。他们对 Claude Code 在 SWE-Bench 上 60 个任务的剖析显示，同一仓库累计至少 5 个任务后，约 30% 的工具调用在重复更早任务，跨仓库对照只有约 7%；每轮加载 23 个工具说明，其中 16 个从未被调用；失败任务只占 17%，却占支出约 32%。在 277 个任务、6 个仓库、5 组 Agent 与模型组合上，相对默认的较强推理设置，平均费用下降 18.4% 到 30.9%，Pass@1 多数组上升，Opus 4.8 仅下降约 1.0 个百分点。节省是逐渐显现的，多数仓库要到第 6 个任务，累计费用才转便宜，工具裁剪贡献最大。[原帖](https://x.com/shao__meng/status/2122507586541166850)

看法：三篇其实是同一件事，模型聪明不等于能在你的约束里可靠干活，先改文档、工具和外围控制，往往比换模型更划算

## 小墨同学 @xiaomovps

**Claude 官方那篇代码验收，他总结了三条**：不要只看 Agent 有没有交差，尽量让它自己跑项目、跑测试，前端最好再看截图，自己也打开页面检查。简单重构和改文档可以多交给它，数据库、权限、登录这类核心逻辑还是要人看，尤其要确认有没有把原来的功能打坏。修 Bug 也要有限度，连续几次搞不定就该停下来换思路，别让它反复改、空烧 Token。他现在更倾向于让 Agent 不但写代码，还要交测试结果，再按任务重要程度决定自己查多少。原文是 Claude Code 官方团队的分享。[原帖](https://x.com/xiaomovps/status/2122642096385577102)

**选 Harness 不再比谁功能多，而是看能不能接着改自己的工作流**：DeepSeek Harness 桌面端方便，很多功能不用自己配，对新手更友好。但他更倾向 Pi，理由是可控、Extension 生态能按需组合，以及 Skills 和配置可以长期留用，模型则随时能换。Pi 的插件也不是越多越好，Orbi 作者测过 20 个插件，有的会改原有配置，有的无法在后台正常跑，还有权限插件会拦住普通命令。他的建议是贵在精，长期跑的 Personal Agent 最好固定一套验证过的组合，更新前先测。[原帖](https://x.com/xiaomovps/status/2122604258885562572) · [插件](https://x.com/xiaomovps/status/2122621363521253706)

**DeepSeek Harness 只装 3 个插件，就串起自媒体工作台**：ModSearch 负责热点和资料，dsh-media-desk 负责文章、脚本、灵感和排期，还能按以前的文章整理写作风格，dsh-guizang-design 负责小红书卡片、公众号头图和长图。找选题、写内容、做设计，这条链路被接上了。[原帖](https://x.com/xiaomovps/status/2122587412849111160)

看法：验收那三条最能下手，Harness 怎么选可以再争，但质量和停点必须人来定

## Ding @dingyi

**用刚上线的 Qwen4-Max，按 ThreeUI 做了杭州主题插画 Sketchbook**：他参考 Meng To 的 ThreeUI，测了两种提示词。一句话提示词很快复刻了页面结构；详细提示词进一步约束杭州场景、翻页、放大镜、墨色调节和导出，成品的内容和交互明显更完整。他有三点感受：长任务和深度推理都很强，很多时候不必再堆一堆 Skill，把需求说清楚也能做完。缓存命中率提高，价格下来了，这次一共用了 1931 万 token，标准套餐还剩 98.3%，按此估算大约有 10 到 11 亿 token，比以前更耐用。提示词仍然很重要，同一主题下一句话和复杂提示词差别很大，建议先让模型多想想，有明确设计计划再动手。[原帖](https://x.com/dingyi/status/2122646340270502127)

看法：模型变强之后，Skill 可以少一点，但计划不能省，先想清楚再跑，比一上来就生成更省事

## Gorden Sun @Gorden_Sun

**美团开源 LongCat-Video-Avatar 1.6，音频驱动数字人能到 10 分钟以上**：按音频、文本、图像生成单人或多人说话视频，重点改善了唇形同步，减少嘴部僵硬和画面闪烁，长视频续写时人物外观也更稳住。他说仅次于 OmniHuman 2.0，MIT 协议，权重可免费下载，也能商用。[原帖](https://x.com/Gorden_Sun/status/2122512201798021267)

**Virtual-Flow 用几个真麦克风，去逼近麦克风阵列的降噪效果**：Meta Reality Labs 和韩国科学技术院的工作，面向蓝牙耳机、AR 眼镜和助听器这类塞不进很多麦克风的设备。方法是用 4 个真实麦克风的录音，直接生成 12 个虚拟麦克风信号，训练目标由真实录音的时间延迟叠加构造，再配合 Reflow 蒸馏把生成压到单步计算。硬件上只有 4 个真麦克风，表现接近 16 麦克风阵列，也能适配 2 到 3 个麦克风的眼镜或耳机，延迟 16 毫秒，能跟实时通话。[原帖](https://x.com/Gorden_Sun/status/2122587251016442041)

## 小工具

**Mole**：Tw93 做的终端工具，把清理、卸载、磁盘分析和状态监控放在一起，免费开源。能逐层找出大文件，清缓存、日志和卸载残留，卸载 App 时也可带走配置和自启动项，还能看 CPU、内存和磁盘读写。支持接到 Claude Code、Codex、Cursor，清理前可用 `--dry-run` 先看清单。注意免费开源的是命令行，原生 Mac App 是单独产品。蓝哥因为 1T 硬盘只剩约 30G，专门录了用法。[原帖](https://x.com/0xlangeai/status/2122642912639148490)

**DS Bot**：基于 DeepSeek Harness 的开源协作工具，用 Chief 协调多个 AI 助手，支持群聊、任务委派、Goal 管理和独立记忆，也能接入本地的 Claude Code、Codex CLI、Cursor CLI。和偏云端的 Grok Bot 不同，它更侧重本地组织，支持 Windows、macOS、Linux 和 Docker，Apache 2.0，软件免费，模型费用自理。[原帖](https://x.com/abskoop/status/2122604272638660966)

**Snug**：接昨天的 UU 远程伴侣，@zephyrxiang12 又做了这个项目。专属竖屏按手机尺寸铺满 Mac 窗口，终端字号自动放大；用启动器式的 App 资源库，一点就把应用丢到虚拟屏；按机型算比例，内置约 800 款机型，减少黑边。开源免费。[原帖](https://x.com/lxfater/status/2122652625661227464)

**DeepSeek 网页版开始限频，小墨收了 3 个免费备用处**：NVIDIA Build 和魔搭社区都可体验 DeepSeek V4.1 Flash，也可申请或使用带额度的免费 API；经常写代码的可以看 OpenCode 里限时免费的 DeepSeek V4.1 Flash Free。都有速率或次数限制，以平台最新规则为准。[原帖](https://x.com/xiaomovps/status/2122567802905395315)
