看法：模型已经够用，真正卡人的是套餐门槛和配套客户端，他把细则写清楚了

## 小墨同学 @xiaomovps

**研究这么多 Agent，他越来越觉得 Harness 才最值得深入研究**：他折腾过 Pi Agent、DeepSeek Harness、Claude Code、Codex 和 Hermes Agent，发现同一个模型在不同 Harness 上表现可以差很多。他归纳成三件事：上下文怎么保留和压缩，长任务中途卡死之后怎么恢复，以及任务说完成了之后怎么验证结果。他也希望国产 Harness，比如 DeepSeek Harness 和 WorkBuddy，能把这三块做强。这篇有 252 个赞、246 个收藏。[原帖](https://x.com/xiaomovps/status/2123807628161916952)

**刚用 Harness，先做好这 3 件事，比装一堆插件更有用**：先让 AI 根据项目生成 AGENTS.md（Claude Code 里主要是 CLAUDE.md），写下结构、技术栈和规范。Skills 不要一上来装满，先从浏览器、代码审查、文档这些常用功能开始。复杂任务要先规划、再执行、最后让它自己跑测试，简单任务就不必搞这么重。这篇有 10 个赞、14 个收藏。[原帖](https://x.com/xiaomovps/status/2124062894942044369)

**虽然讨厌 Anthropic，他还是整理了 8 个值得收藏的学习站点**：包括免费课程 Claude Academy、工程博客 Anthropic Engineering、Claude Code 文档、Platform 文档、研究论文、应用案例、Cookbooks，以及官方 Skills 开源库。他给了三条路线：小白从 Academy 和 Resources 进到 Code Docs，做 Agent 的看 Engineering、Platform 和 Cookbooks，研究 Harness 的看 Engineering、Research 和 Skills。很多资料有中文版。[原帖](https://x.com/xiaomovps/status/2124093967654679005)

**有人拿 Claude 合作宣布证明黎曼猜想，他也写了这件事**：他说 Anthropic 数学家 Levent Alpöge 宣布和 Claude 合作找到了证明，并公开了 1700 多万行用于验证的代码。另一位数学家 Alessandro Masullo 已经研究了将近 12 年，原本还准备再花一年完善，看到这边进展后选择提前公开。小墨也写了折扣：这些主张还要数学界继续审查，人工证明里已经被发现一些问题。他的感受是，AI 开始改变前沿研究的节奏，人更要把精力放在提问、判断和验证上。[原帖](https://x.com/xiaomovps/status/2124078121792217276)

看法：他反复讲上下文、长任务和验证，说明现在差的不是再多一个模型，是把活真正跑完

## meng shao @shao__meng

**面试里总听到「我们想训自己的模型」**：对方说某某模型不行、不懂他们的行业，可再问具体哪里不行、要提升哪方面、手里有哪些数据，往往说不清，只强调做了很多年、数据是壁垒。他后来只好回「哦，好」。他觉得企业总是轻看知识库、RAG 和实时检索，对绝大部分场景这些才更现实，动不动就训行业大模型，可能还没想清楚知识和权重的差别。[原帖](https://x.com/shao__meng/status/2124055923589316932)

**腾讯团队开源 LoopForge，五个定时 Agent 维护自家仓库**：人只在「做什么」和「哪条 PR 能合并」两处做判断。五个错开的定时任务分别负责调研提需求、评审、处理 CI 冲突、给覆盖偏低的包补测试、对照 AGENTS.md 做结构性整理。补测试时写死只能加新测试文件，不准为了让测试通过去改业务逻辑；架构类 PR 积到 10 条就停。不可逆操作写在提示第一行：不合并、不关闭、不直接推主分支、不动同事的分支。团队也说这套设置花了数周调校，数字来自他们自己的一个 Go 仓库。这篇有 19 个赞、20 个收藏。[原帖](https://x.com/shao__meng/status/2123977246494818582)

**Langfuse 工程师谈主动式 Agent 该怎么评**：Annabell Schäfer 写了 Evaluating proactive agents，核心是 Agent 会自己决定要不要行动、何时行动、介入多深，该做却没做的事往往不会留下失败记录。她建议把「保持沉默」也记下来，分开看三类错误：行动太勤造成打扰、过于保守漏掉该做的事、介入过深本该先问却直接执行。评测样本要从「问题和标准答案」扩展成「情境和应有判断」，花钱下单和轻提醒也不能共用同一道门槛。这篇有 10 个赞、14 个收藏。[原帖](https://x.com/shao__meng/status/2124043580415385946)

**Matt Pocock 做了给非开发者用的第一个 Skill /vector**：用 VECTOR 六问，把现有工作流画成可验证、会记忆的流程地图，走完后得到一条能委托给 AI、还会随时间变好的工作流。他计划再放配套框架和文档，方便公司自己组织讨论。[原帖](https://x.com/shao__meng/status/2123948393009422679)

看法：企业开口就要训模型，往往还没想清楚知识和权重的差别

## 思维怪怪 @0xLogicrw

**姚顺雨和混元团队在 Reddit 问答里谈到下一代模型**：有开发者问，字节和 Kimi 都在探索数万亿参数，为什么混元还停在大约 7000 亿。团队的回应是，较小但训练扎实的模型也能超过更大的模型，而且更便宜，但他们仍然相信 Scaling Law，下一代 Hy 会显著扩大参数规模，现有 Hy4 也会靠大规模强化学习继续提升。他们还计划推出能在个人电脑上本地跑的 Hy4-mini 和 Flash-Lite。这篇有 21 个赞、9 个收藏。[原帖](https://x.com/0xLogicrw/status/2124008357153669322)

**Thinking Machines 推出能在笔记本上跑的 Inkling 2 Mini**：Small 版有 5940 亿参数，至少要 500GB 显存；Mini 降到 264 亿，每次生成激活 34 亿，采用和 GPT-6 Astra 一样的循环 Transformer，24 层里中间 12 层会重复跑 3 次。Artificial Analysis 综合评分 20.1，与 Qwen3.8-27B 持平，单项评测成本大约是后者的六分之一。DeepSWE v1.1 通过率 48.2%，高于 Qwen 的 42.2%，办公自动化则低于 Qwen。完整权重是 Apache 2.0，官方版本大约 20GB，可在 32GB 内存的 Mac 上离线跑，Unsloth 还有 16GB 就能跑的量化版。[原帖](https://x.com/0xLogicrw/status/2123982609189671073)

**字节再次调整 AI 组织**：Seed 新设二级部门 Seed Model-MaaS Infra，原火山方舟团队更名为 Seed MaaS，都由吴迪负责，他向项亮汇报，同时向谭待汇报业务。这样企业客户在方舟遇到的问题，可以更直接反馈给 Seed。他也写了，今年上半年火山引擎 MaaS 业务收入达到 48 亿元，毛利率超过 55%，字节从年中开始更看重实际收入，而不只是调用量。[原帖](https://x.com/0xLogicrw/status/2124045308384715235)

看法：混元一边认 Scaling Law，一边先把能在电脑上跑的小模型做出来，路子比较实

## Barret李靖 @Barret_China

**AI 时代更需要人的主观能动性**：过去互联网白领分工很细，职能部门边界很强，大家都擅长解决自己领域里的单点问题，却很少有人能站在全局看一件事。大厂职级里常说点、线、面，先把一个模块做到极致，再把几个点串成线，再往上才是业务和组织视角。可 AI 对人的要求更立体，强调端到端交付，一个人既要懂业务也要懂技术，能独立判断和把事情推落地。他觉得这正是当下组织转型的阵痛：过去十几年都在训练分工，现在却突然要求打破边界，独立面对一个完整问题。这篇有 51 个赞、35 个收藏。[原帖](https://x.com/Barret_China/status/2123955560680943982)

看法：分工把人训细了，AI 却要求一个人把事从头看到尾
