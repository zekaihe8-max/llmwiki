# 中文推特圈每晚精选 · 2026-10-30

## 今日主线
- OpenAI 把 Pro / Business Premium 用量翻倍并取消原定降额；Claude 侧则是 API 请求上限 32MB→128MB、回答后自查「自我评估」
- Grok Bot 生态继续扩：夸克网盘 Skill、两分钟上线站、五开源替代、Pages 报表、烤箱做叉烧；Magpie 显化「只做多账户切换」
- Agent 工程向：阿里云开源 AI Agent Handbook、Addy 谈少堆提示、Pi Durable 事务减 82%、DSH Android、Cursor 扩展商店 Claude Code 插件被投毒

## 宝玉 @dotey

**baoyu-design v2.1 评论**：昨天刚开源的 Design 全家桶补上评论；可在页面 / slides 上标记元素写意见，Agent 能读也能回，评论跟项目数据一起存。[原帖](https://x.com/dotey/status/2116060639533969759) · [仓库](https://github.com/jimliu/baoyu-design)

**Claude API 单次请求 32MB→128MB**：Messages 和 Token Counting 上限约四倍，长截图、大 PDF 不容易再卡在「窗口还有余量、请求体已满」；仅官方 API。[原帖](https://x.com/dotey/status/2115968852349567254)

**Claude 回答后自查「自我评估」**：每条回复后模型先给安全初评，算力 Anthropic 出、不向用户收费、不额外收数据；自称单条标记不会直接封号，宝玉猜测也防蒸馏。[原帖](https://x.com/dotey/status/2115923359149998490)

**OpenAI Pro 用量翻倍**：Tibo Day25 宣布 Pro 100/200/500 与 Business Premium 上限翻倍、当天生效，原定 Pro 200 降额取消；Plus 不在名单里。[原帖](https://x.com/dotey/status/2115856411439575386)

看法：评论把 Design 从「出图」推进到「人机改稿闭环」，API 体量与自查是 Claude 侧两条硬基建。

## meng shao @shao__meng

**阿里云开源《AI Agent Handbook》**：企业 Agent 全生命周期（架构 / 构建 / 运行 / 治理 / 调优）实践手册，核心叙事是用 Harness 把试点推进到可治理生产；调研称真进生产约 18%，上下文 / 记忆需求约 90%。[原帖](https://x.com/shao__meng/status/2115975663148765204) · [仓库](https://github.com/aliyun/ai-agent-handbook)

**Addy：Opus 5.5 时代少堆提示**：Claude 5 系列后，长系统提示、强制拆子 Agent、人肉盯多会话往往只加成本；更有效是写清目标与验收，让模型自己跑完再停。[原帖](https://x.com/shao__meng/status/2115986116482613486)

**Cursor 云端电脑「看着真 Slack」做成代码视频**：mattyp 演示 Why → computer use → Video as code → Skills → Feedback loops；Agent 复刻界面当视频素材。[原帖](https://x.com/shao__meng/status/2115991611306086574)

**方寸 Leap 对 DeepSeek V4.1 Flash-1017 的 87 页安全评测**：国内第三方实验室盯失控与有害操纵，结论相对 V4 一代有变化，可当开源模型安全对照读。[原帖](https://x.com/shao__meng/status/2115999263121699221)

看法：Handbook 适合企业侧收藏，Addy 那条和今天大量「省额度 / 少说话」帖是同一方向。

## 小邓同学 @heydengai

**/autocompact 400k 省周额度**：1M 上下文默认近 97 万才压缩，历史越积越贵；有人实测提前压到 40 万可约省 29% 周额度。[原帖](https://x.com/heydengai/status/2116121434326261778)

**Sol vs Opus：比任务别比 Token**：同 $20 档，按 API 等价 Sol 贵约 7 倍，按完成单任务只贵约 1.3 倍。[原帖](https://x.com/heydengai/status/2116127987095806159)

**压缩可能走错方向**：转述「不压缩、完整会话按需检索」思路；实测 40 万 Token 会话上按需检索可比缓存失效压缩更便宜更快。[原帖](https://x.com/heydengai/status/2116019898422083808)

**少说话多验收**：读完 Addy 文后的压缩版工作法：目标与检查标准人定，中间让它自己跑自己审。[原帖](https://x.com/heydengai/status/2116029608818815439)

看法：autocompact 和按需检索是今天额度焦虑里最可执行的两条，任务成本对比比空吵「谁贵」有用。

看法：投毒是今天最该立刻检查插件版本的一条，Code Mode 和脑机唤起分别是效率与入口极端。
