# 谷歌 Neon 加 MAGI-2 居然这么强！解锁 AI 写代码与生视频的双向玩法（附 Skill）

5 min read

在 LibTV 玩了几天新上的视频模型 MAGI-2。

这模型确实厉害，生成质量基本上追平了第一梯队的水平（当然第一梯队现在只有一个模型）。

[/op7418/article/2125531062541635755/media/2125528976978587648](/op7418/article/2125531062541635755/media/2125528976978587648)

同时功能也比较齐全，支持 30 秒的 1080P 视频，以及多图、多参的混合参考。更主要的是价格便宜得离谱，5毛/秒，LibTV限时特惠5分/秒，5 秒的视频也就两毛五。

我最近一直在研究 Agent 和视频模型结合能有哪些玩法。

刚好最近 Google Neon 也比较强，而且 MAGI-2 非常便宜，提示词理解又好，还能支持长达 20,000 字的超长提示词。

所以这次就分享如何用 LibTV 的MCP，把便宜好用的 MAGI-2 和代码、审美能力很强的 Google Neon 结合起来，跑通 Video 2 Code 和 Code 2 Video 这两套内容生产流程。

### 基础测试表现

先简单看几个我跑的基础测试。

第一个是敦煌飞天视频，人物形态非常稳定，大幅度的空中旋转和飘带动作都非常自然。

第二个是暗调逆光的竹林武侠场景，主要测复杂动作，运镜和跟拍的表现都不错。

第三个测了智能与理解能力。

我先生成了一张带色块滑块的 UI 图，让模型基于图生成视频。当滑块滑到对应色板时，整个场景就会变化成对应的色板，说明它能理解这种逻辑并完成调色操作，这个很厉害。

第四个是文字渲染能力。

比如咖啡的视频里，在吐小票、盖章和点击屏幕时，文字出现完全没有以往视频模型常见的果冻效应、晃动或伪影。在做动画以及文字与视频混合的效果上，表现非常好。

最后一个是物理模拟测试，测了常见的硬度变化小球效果。整体还挺好，只是最后阶段对小球体积的估计可能不够准确，在硬度降到零时水变出的量有些偏多。

目前整体看下来主要有两个小问题：

一个是提示词润色有时会有偏差，已经反馈给官方在修复了。

另一个是音频方面，背景音乐和动作音效有时配合不好，经常二选一只出来一个，这个也正在修复，过几天应该就会改善。

### 玩法一：Video to Code（视频转网页代码）

接下来看两大核心玩法。第一个是 Video to Code，也就是视频转网页代码。

我先做了一个视频，包含图形、飘带和连续的转场动势，然后让 Neon 基于这个视频完成了一个一镜到底的产品官网。

网页在滚动时元素是持续平滑变化的，这种效果如果单纯靠提示词让 AI 直接写代码，其实很难一下就写好。

具体做起来其实挺顺的。先在 LibTV 中生成一个六宫格分镜模板喂给 MAGI-2，具体的图片和视频提示词我直接截在图里，省得占太多字数。

[/op7418/article/2125531062541635755/media/2125530206874324992](/op7418/article/2125531062541635755/media/2125530206874324992)

视频出来以后，让 Neon 读取这段视频的配色和转场动势，写出一个一镜到底的视差滚动网页。Neon 第一版就完成得很好，后面只微调修复了字体排版和个别动画闪烁的问题。

[/op7418/article/2125531062541635755/media/2125530381114032128](/op7418/article/2125531062541635755/media/2125530381114032128)

声音这块还可以和交互结合起来

MAGI-2 生成的视频只有音效没有音乐，我让 Neon 用代码生成了一段电子乐混进视频，更妙的是因为电子乐的 BPM 可控，直接将其放进网页作为背景音乐，页面滚动越快，BPM 就越高，非常有意思。

另外素材也能双向复用，在 LibTV 里生成的透明底产品图，可以反过来作为网页的图片素材直接复用。

[/op7418/article/2125531062541635755/media/2125530449263116288](/op7418/article/2125531062541635755/media/2125530449263116288)

如果让 AI 凭空写产品官网并用 CSS 绘制，效果往往很土。

但如果先用视频把视觉参考定下来，再让 AI 对照着写，效果就会非常好。

以前这种工作流跑不通是因为好的视频模型太贵，而现在 MAGI-2 算下来一条视频才几毛钱，而且是一次成片不用抽卡，成本低了很多。

### 玩法二：Code to Video（代码转视频控制）

既然能先生成视频再转成官网，反过来能不能先用代码生成动作参考，再去精准控制视频模型？

这样我们就能实现精准控制：先让模型不断修改代码生成的动作，直到完全符合要求，再去生成最终视频，成本非常低。

具体做法是先让 Neon 写代码生成一段 2D 横版 Boss 战的动作灰盒视频，包含跳跃、弹反、顿帧、镜头特写以及连招位置等动作细节。

[/op7418/article/2125531062541635755/media/2125530698312466432](/op7418/article/2125531062541635755/media/2125530698312466432)

注意这里不要带音频，避免音频干扰视频参考。

接着在 LibTV 的画布中利用全能参考功能，将设定图和这段代码生成的视频结合起来，直接精准控制生成一段水墨风格的游戏打斗视频。

把我们的设计图和代码视频都放到输入里，再用提示词实现对代码部分完整的水墨画重绘，以及音效和音乐的添加。画布连线和提示词同样放截图里供参考。

这样做有个好处：如果动作不满足需求，它可以一直去修改。

我觉得现在大语言模型和图像、视频模型的融合趋势非常明显：

大语言模型越来越理解图像和视频，也更容易去生成它们；而图像和视频模型则越来越能理解复杂的语言提示词，以及用户的真实需求和想法。两者的结合在内容生产上能带来非常大的帮助，比如降低成本、提高可控性与最终效果。

最主要的是视频模型成本的降低，会带来非常多的新玩法。

如果不是专门做短剧的，很多人其实不太愿意花那么多钱去买、去玩视频模型，因为成本太高了。我觉得 MAGI-2 在这个时候推出非常合适。

未来 Agent 结合视频与图像模型，一定会有更多玩法的可能性，绝不仅仅是用来做短剧或剧情视频。

希望这个玩法能给大家带来更多启发和好玩的创意，也可以去 LibTV 尝试 MAGI-2 模型，他们现在优惠挺大的。
