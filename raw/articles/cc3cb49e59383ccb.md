Rex has really powerful Lua scripting that our beta group has been using to huge effect. We expanded it today with `rex.ui`: a way to build automations that require user interaction.

The way this works with multiple clients: the choice pops up on all attached clients. The first client to respond wins (and hides the prompt from the rest).

If any client is already showing a prompt, we respond with a "busy" error code and let the Lua script decide what it wants to do (sleep, try again, force it, etc.). This will surely improve, but the API gives us flexibility to improve it later.

If no clients exist, another error code Lua can detect is returned noting that no user is attached, and it can decide what it wants to do.
