主题：通过 Grok Bot 内置 X 检索能力，让 Codex 等 Agent 低成本获取 X 数据，替代付费 X API，并提供 Webhook + Cloudflare Worker 与 BDK + MCP 两种可跑通的连接方案。
1X API 成本
普通帖子读取每条 0.005 美元，每读 1000 条需 5 美元。若每天替代 1000 条付费读取，一个月可少花约 150 美元。计算依据是帖子读取量而非搜索次数，一次搜索返回数量、是否重复或额外获取用户资料均会影响实际账单。
2Grok Bot 额度
Grok Bot 自带公开 X 搜索与读取能力，每天有 1000 次内置工具调用额度，每分钟 30 次。还可通过插件连接自己的 X 账号，查询收藏、首页、私信与粉丝名单。
3两种连接方案
方案一：自己搭建 Webhook + Cloudflare Worker + D1，实现任务派发、领取、回传与存储，含幂等、任务编号与失败重传。方案二：使用 Cursor BDK（@cursor/bdk）启动本地服务，通过 MCP 直接联系指定 Grok Bot，配置更简单。默认推荐先用 BDK 跑通，再按需决定是否加 Webhook。
4一句话原理
Codex 把研究问题交给 Grok Bot，Grok Bot 用自己的内置 X 工具查询，再把资料和原帖出处交回 Codex，在原会话里继续分析、写文章或做产品调研。
核心内容与未来现实行动指南
1先在 Grok Bot 中创建专门的「X 研究员」Bot，明确职责，并配置自动化任务：收到外部请求后按要求搜索 X 并回传结果。
2Webhook 方案：让 Codex 用 Wrangler 部署 Cloudflare Worker 与 D1，配置四个核心接口（提交、领取、回传、查询），生成 Python 回传脚本，先做握手测试（不搜索），再做真实搜索（如最近 30 天帖子，限制搜索次数与结果条数）。代码与接入说明已放在 GitHub：[github.com/bytec-ai/grok-…](https://github.com/bytec-ai/grok-x-bridge-example)
3BDK 方案：安装 BDK（Node.js ≥22.13），登录拥有目标 Bot 的 Cursor 账号，创建桥接项目，修改 grokbot.ts 中的 Bot 完整名称，启动本地服务，把 MCP 接到 Codex（临时或保存配置），通过 call_tool 发送完整研究任务。Bot 沿用自己的会话与工具，但 Codex 不能读取 Bot 全部历史聊天。
4选择建议：大多数个人场景先用 BDK；若主要跑在 Worker 环境、不想维护常驻进程，或希望 Bot 主动回传到业务接口，再选 Webhook。保存结果、定时查询可在 BDK 外层加存储与调度。
5立即行动：把原文丢给 Codex，先用 BDK 接上，挑一个正在研究的问题（选题调研、竞品分析、AI 工具真实体验）让它去 X 查一轮，确认结果后再接入日常工作流或自己的 Agent 产品。
金句总述
X 的信息密度很高，让 Agent 把一手讨论和原帖链接查回来，就能在原来的会话里继续分析、写文章、做产品调研，还能把检索做成产品能力。
阿策原本用 Codex 做 X 账号运营分析，每次走 X API 读取帖子，普通读取每条 0.005 美元，读 1000 条就要 5 美元。玩上 Grok Bot 后发现它自带每天 1000 次的 X 工具调用额度，于是想到让 Codex 直接找 Grok Bot 查，把费用省下来。之所以不直接在 Grok Bot 里做，是因为很多项目已经深度用在 Codex 里，迁移成本高，而且正在做的 DraPub 产品也需要检索 X，正好提前把链路跑通。他先让 Codex 搭了一套 Webhook + Cloudflare Worker + D1 的桥，任务提交、触发、领取、回传、查询分开处理，加了幂等键、任务编号、失败重传和结果校验（帖子 ID 与 URL 一致、不重复、结论引用来源、不超数量）。后来发现 Cursor 的 BDK 可以直接把联系指定 Grok Bot 的能力做成 MCP，配置简单很多。两条路都跑通后，他把详细步骤、可复制的任务说明、Python 脚本、本地 CLI 和示例查询都写进了文章，并在回复里放出了 GitHub 仓库链接。实测一次“最近 30 天 Opus 5.5 制作视频相关帖子”的中英文检索，从提交到结果入库约 162 秒，返回 6 条帖子，Bot 报告用了 3 次搜索。最终建议：已经在用 Grok Bot 的朋友，把文章丢给 Codex，先用 BDK 接上，挑一个正在研究的问题让它去 X 查一轮，从一次选题调研或竞品分析开始，觉得好用再接进日常工作流或自己的 Agent 产品。
