Addy Osmani：Coding Agent 让你成了管理者，但不该让你更忙

当你开始挑任务、交代背景、委派工作、验收结果，你已经在 “管理” Agents。多开几个会话本身意义不大，重要的是建立让 Agents 能自行验证、带着证据交付的工作方式。

# 先让 Agent 能检查自己，而不是让人充当测试系统

Addy 把自验证放在首位：每项任务都应提供可执行的检查，例如测试、构建、类型检查，界面改动还可以用截图验证。

Agent 应先执行、检查、修正失败，再提交结果与证据，而不是说一句“完成了”，把所有验证留给人。必要时，再让没有参与原对话的新 Agent 独立审查，减少沿着同一思路自我认可。

# 最该补充的是仓库里看不到的信息

任务说明不必重复代码已有的内容，更重要的是：为什么做、业务约束是什么、哪些事情不要做，以及怎样才算成功。

重复出现的纠错可以沉淀为共享规则或技能，但规则不是越多越好。随着模型升级，旧约束也要清理；普通偏好可以写成指导，必须遵守的安全要求则需要强制执行机制。

# 并行的上限，往往是人的注意力

无人值守任务开始前，要明确完成条件、验证方式、权限、运行上限、交付产物和审批人。新流程先小范围试跑，再扩大规模。

即使测试全绿，功能也未必值得做。产品取舍、安全边界与发布判断仍由人负责；成效应看交付周期、返工和回退，而不是 Agent 写了多少代码。
