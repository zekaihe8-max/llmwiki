# Thariq Shihipar：Bitter Lesson 的甜蜜一面 -- 用可读规格和自制脚本语言，把创作控制权留在开发者手里

9 min read
[/i/web/status/2123514398438211840](/i/web/status/2123514398438211840)

前 Claude Code 核心开发者，目前的独立开发者 Thariq Shihipar 在 AI Engineer Code Summit 2026 做了这场主题演讲「The Sweet Side of the Bitter Lesson」，讲的是他离开 Anthropic 之后这一年的反思。副标题 or, all the ways I've been wrong 也很值得回味。人们常把「苦涩教训」理解成模型会按自己那套怪异方式行事，人只能接受。他看到的另一面是：能力一旦进入足够熟练的区域，模型就可以按人希望的方式工作。他把这称为苦涩教训的甜蜜一面。他自己用 vibe coding 做格斗游戏时，一度连角色机制都说不清，便从这里去找把控制权拿回来的办法。

### 他猜对了三件事，也把 Bash、React 和扩散模型想窄了

他先承认自己这一年也猜对了不少：模型能够生成和编辑视频，这件事他大约在去年六月就谈过；模型可以用 HTML 来理解自己的工作；还能帮人弄清未知，去做计划和学习。可下面这三件，后来都没有按他当初的想象发展。

第一件是「Bash is all you need」。有那么一段时间，智能体特别会用 Bash，Claude Code 也是围着 Bash 工具搭建的，于是出现一种风气：要把所有东西都变成命令行，连 MCP 也通过 mcp-cli 去调。他现在更喜欢直接用 MCP，而且旁边还出现了 Code Mode、Skills、渐进式披露，智能体作用于世界的方式远不止一种。早期它们爱用 Bash，更像是一开始被怎样训练留下来的痕迹。

第二件是「React is all you need」。模型一度写 React 写得很顺，好像要做 AI 应用，就该上 React、React Native，或者把所有东西都放到网页上。他也担心过，模型主要在 React 上训练，React 几乎会变成最后一门语言。后来的情况不同了：模型现在能写 HTML、React、Swift，也能写 Figma 的专有 JSON，做出来的东西大致都说得过去。他看到，已经有不少人在写自己的语言。

第三件是「Diffusion models will eat art」。他担心扩散模型会把艺术「吃掉」，人控制不了模型，也控制不了它们做出的作品，只是画面会非常漂亮。这一条同样没有发生。大语言模型现在可以通过写代码、操控电脑，使用 Blender、Photoshop、Figma 这些原有工具，按人做艺术的方式去工作。

他把这三类担心，都归到人们对苦涩教训、外星智能、Shoggoth 的想象上：模型会有一套怪异的做事方式，人只能接受，甚至只能臣服。在他看来，后来并没有走到那一步。

### 软件工程处在采纳最前线，工业革命和文艺复兴同时发生

于是问题回到：怎样才能既对 AGI 真正上心，又把人放在中心？原话是 How can we be AGI-pilled and human-centered。他认为这件事特别要紧，因为软件工程师正处在 AI 采纳的最前线：软件领域正在发生的变化，随后也会发生在知识工作和经济的其他部分。会上也有人谈对抗 slop、把目标设得更有野心，他觉得软件工程师是第一道防线。

对 AI 本身，他愿意同时用两个词来看：工业革命，和文艺复兴。他觉得这一年主要是工业革命。大家常说 software factories，软件正在从一种不可靠、很难推进的手艺，变成不再构成限制的东西。工业化正在发生，文艺复兴也同时在发生：人们想要质量更高的软件，多放进去的每一点创造力、用处、精神、灵魂，都有用，而且有经济价值。幻灯写得更干脆：工业化比的是更快、更稳、更便宜地交付；文艺复兴要交出人们从未见过的东西，能找到的每一点优势都有用。

### 锯齿前沿人人都在看，他更看重前沿以内的平滑内部

谈论模型能力时，人们常说 jagged frontier，也就是锯齿前沿。他顺着这条线往回数：大约两年前是让模型写一个函数，一年半到一年前是做一个功能，再往后是做一个简单的待办应用，然后「帮我做个 Slack 克隆」；现在已经变成「从零做一版马里奥赛车」，甚至还要移植到 Wii。评测和基准里，大家看到的就是这条不断往上蹦的能力边界。

[/shao__meng/article/2123595391077875984/media/2123589041132081152](/shao__meng/article/2123595391077875984/media/2123589041132081152)

他真正想强调的，是这条前沿里面的 smooth interior，也就是平滑内部。模型变强的时候，能力不只是在边界上往外戳，也会沿水平方向变宽。会写 React，也就能写 Figma、写 JSON，有一大片任务模型都已经相当熟练。对他来说，这一点甚至更要紧。他已经不太关心模型能不能从零做出马里奥赛车，更关心做出来的软件质量够不够高，配不配得上一次文艺复兴。

因此，如果问题已经落在模型能力很够用的区域里，人就可以按自己想要的方式去要结果。做一份设计稿，可以要 HTML，可以要 React，可以要 Figma 文件，也可以让模型操控电脑，打开 After Effects 去出一条视频。路径不必只有一条。他曾经很怕模型只会热爱做某一件事，所有人就只能跟着做那一件事。

把这个判断再推远一点：今天为模型搭建的运行框架、软件工厂和脚手架，以及「人的工作是给模型做验收、做代码审查」，在他看来都不会一直成立。模型越来越聪明，会把更多事情推进这块平滑内部；他想象中的完美模型，不必再核对自己的工作，也不必再去扫安全漏洞，只要按规格和目标写下正确的代码，人对照一看就会发现它做对了。幻灯上写得更硬：今天仍需要运行框架去兜住的许多事情，将来很可能不再需要。

### 一张世界地图，用来看见模型到底记住了多少

为了把「一般知识」说得更具体，他展示了一张题为 How much each model has memorized from pretraining 的图，子标题是 How 12 blind Claudes see the Earth。方法是：在地球上每隔 2 度取一个点，一共 16,200 个点，不给图像、不给工具，只问这是陆地还是水面，再把回答「陆地」的点画成白色。他特别点了两个模型：Opus 4.6 作为相当强的软件工程模型，准确率 91.2%，看去仍像一张有些模糊的地图；再看 Opus 5.5，准确率到了 99.0%，几乎已经接近完整的世界。

对他来说，锯齿前沿已经越来越不像最重要的那件事，更要紧的是模型拥有的一般知识。让他感到兴奋的是：人可以用智能去理解、并塑造自己如何使用智能。他认为这会成为下一年的主题。这一年更多是在把软件生产工业化，找到一种可靠的做法；接下来要问，那种可靠之后，工作本身应该是什么样子。

### 当 vibe coding 让人失去对作品的感觉，他把引擎和可读规格拆开

于是他讲到自己正在做的游戏。这是一款二维等距视角的格斗游戏，灵感来自《降世神通》和《任天堂明星大乱斗》，他也在 X 上发过，做起来却很挫败。他很想做一个出色的 vibe coder，把想法丢给模型、边改边看，结果有时连自己的角色到底会什么都不清楚。比如他会说「让这个角色扔一块石头」，模型确实做了，可扔石头时还有许多选择：角色也能召唤一堵墙，石头到底穿不穿墙，速度、大小、蓄力又该怎么算。模型替他做了一堆决定，他试玩之后完全说不清这个角色在干什么。他很容易分心，发出一条提示就去做别的事，再回来时进度更少了。有一段时间他觉得，跟 AI 共事大概就是这样。后来再想，他觉得这样不行。模型其实可以按人希望的方式工作，而这种失控的状态也带不出文艺复兴，带不出真正出色的软件。

他提到会上 Dex 说过的意思：出色的作品，往往来自一团并不一开始就完全清楚目标的过程，关键是探索过哪些设计、做过哪些选择，留下了什么，又没有放进去什么。PPT 上的句子是 Great work is about the designs explored and the choices made。可当他看着自己 vibe coding 出来的结果时，感觉差得很远。幻灯上另有两句更重的话：I don't think this is acceptable. It's not what a renaissance feels like。以及：You simply have to be an expert. You have to know it inside and out。

他的修法还很早，并不声称已经想明白。眼下的做法，是把代码库拆成两部分。一部分是引擎，他不必细读；另一部分是一个他曾叫做 spec、后来想改叫 human 之类名字的文件夹，专门放他会读的代码。这份代码有 lint，也给 Claude 定了规则，读起来要像英语，密度刚好让人读完就知道游戏里在发生什么，也能动手改，并对游戏本身构成一份可核对的事实来源。

PPT 上的例子是一个名为 swat 的招式，用 defineMove 来写，冷却时间写成 seconds(0.6)，避免在逻辑里塞一个裸数字。规则也写得很具体。一条叫 hero-name：要用英雄的名字来称呼角色，不要用 me，让一行代码读起来像一句关于这个英雄的话。另一条叫 bare-number：招式逻辑里不许出现裸数字，数字要在 tune 里起名字。

### 现场演示：给游戏做一门接近英语的脚本语言

演示里，他打开了名为 bending-game 的项目。一边是他称为 agent 代码的部分，比如摄像机如何工作，他并不打算搞懂；另一边则是角色和技能。他点开扔石头的招式，里面有充分的注释，用「米」这类有单位的量来调参数。这个角色扔石头至少有三种路径：从地面抓起，从墙里取出，还可以在碎石之后直接甩出去。他不必知道引擎底层如何实现，等于给游戏做了一门自制的脚本语言。

有了这层语言，他就可以做很细的调整。现场他把石头改得更大，写成 1.5，然后在真正的 IDE 里打开游戏：角色蓄力，石头明显变大，再扔出去。他也开始更多地使用 Cursor 和它的 tab 补全，例如先写下「如果在中间召唤一堵墙，就把它排进动作队列」，再让补全接着往下写。他觉得这有点像规格驱动开发，只不过这份规格本身就是一门脚本语言。

他并不确定这就是自己做游戏的最终方式。遇到更复杂的事情，仍然需要让 Claude 去实现、去准备原语。可理解发生了什么变得容易多了，控制感也强了；Claude 在工作时，他还可以一起审、一起改。

### 下一年若要有软件文艺复兴，先决定理想中的工作体验

对他而言，这次调整留下的收获是：他现在必须思考的，是怎样才能交付高质量的软件。模型能力如何、它更喜欢用哪种语言写代码，已经不太构成限制。如果把这一点真正吃进去，他认为下一年会是软件的文艺复兴。

会上不少人都谈到要把目标设得更有野心。他觉得这些想法并不新鲜，可做的事情仍然很多：新的语言既要像 Rust 那样高效，也要模块化、可热重载，并且尽可能可读；也很可能出现新型数据库和新型服务器；还会有新的操作系统交互，他自己就在用 vibe coding 写一些会动到操作系统的个人软件。许多旧的人机交互研究现在值得重新拿出来看，软件的使用和设计美学也可以大变。幻灯在「文艺复兴可能带来什么」之下，还单独标出了新的个人软件，以及可塑的软件（Malleable software）。

他最后想强调的是：人需要决定未来的工作看起来是什么样子，也需要决定理想中的体验是什么。模型并非一种外星智能，非要把人推进某一种工作方式；它们几乎什么都能做，而且会去做。人的工作，是把这场文艺复兴带来。
