# AI 的流量超过人类之后，搜索也要重做一遍

6 min read

Cloudflare 最近公布数据，他们网页流量里自动化请求已经占到 57.5%，人类只占 42.5%，这是互联网历史上第一次 AI 的流量超过人。

联网搜索几乎是任何 AI 工具必备的基本功能。最近这一轮迭代里，DeepSeek 也发布了搜索 API，腾讯也官宣了向全行业开放「元宝搜索」。

为什么在 Agent 快速发展的今天，联网搜索也要跟着变？下面是我观察到的变化和实测，如果你在开发 Agent 产品，也许能作为参考。

### 需求的变化：从给人用到给 AI 用

搜索的用户，这几年实际变了三次。

最早是给人用的。用户输入关键词，搜索引擎返回十条链接，用户自己点进去读，比的是谁排得准、谁列得全。

后来大模型开始读搜索结果。模型把结果读完生成一段总结，用户直接看答案，比的是谁能把结果读明白、总结清楚。

现在轮到 Agent。Agent 把一个问题拆成几个子问题，挨个去查，拿到结果再自己推理。

人和模型用搜索，差别在判断这一步。人看到十条链接，会点进去读，自己判断哪条可信。模型没有这一步，它拿到的每一条都会进入上下文，直接变成它说出口的话。比如一条营销号，人扫一眼就划走，模型却会把它当成事实引用。

### 新需求带来的三个卡点

搜索的用户从从人换到 Agent 之后，卡点有三个。

结果要能直接用。人读一段摘要就够了，模型需要的是正文。如果接口只给标题和摘要，模型就得再发一轮请求去抓取，抓取慢，会失败，还要处理反爬。

结果要信得过。SEO 农场、营销号、过期页面，在模型眼里和官方公告没有区别，模型只会相信排在前面的那几条。

速度要够快。Agent 完成一个任务往往要串好几轮搜索，单次慢一秒，用户等的是好几秒。

元宝搜索为了解决这些问题，做了三个专门的优化：

第一条，从摘要到正文，模型拿到手可以直接放进上下文，不用再发一次抓取请求，省 Token 省上下文。

第二条，信源有门槛。接入了 13 个行业 157 个权威信源，金融、医疗、政务这几个垂类，提高置信度。

第三条，它在建索引时就把每个网页压缩成 100 个 token 存好，检索时模型直接复用 KV Cache 里这部分，只计算用户那句查询，推理开销不再随文档长度增长。

三条合起来的效果，是 Agent 少调几次搜索。腾讯内部的产品像元宝、IMA 等，换掉原来的搜索之后，完成一个任务的平均搜索调用从 8 次降到 5 次，效果立竿见影。

04 搜健康医疗

我搜索的三条都答对了，但信源质量不一致：幽门螺杆菌阳性要不要治，首条是人民日报；高血压能不能停药，落在中国医药信息查询平台；布洛芬和对乙酰氨基酚能不能同服，落在复禾健康。营销号和医院套餐页都没混进来，这一点比大多数通用搜索接口干净，但第三条只是健康垂类站点，权威性不如前两条。

05 复杂问句

问被英伟达投资过的中国自动驾驶公司，首条是南方新闻网《湾区智驾在下一盘什么大棋》，把几家公司的融资背景串在一起；问跨境电商要办哪些资质，落在肇庆政府网的法律合规指南。三条全中，来源明显偏政府和机构，不是行业媒体。

08 生活服务与本地信息

生活服务方面，可以得到大量信息，但信息不够结构化，也不能进行后续的服务预订，这类信息还是接入 API 比较合适。

09 学术与技术文档

学术搜索方面，感觉结果不太及预期。问 Transformer 原始论文的出处，首条是澎湃的一篇纠错报道，不是 arXiv 原文；问 RAG 和长上下文哪个更适合知识库问答，落在技术博客；只有问 torch.compile 的官方用法时，首条直接是 PyTorch 官方文档。看起来论文这种低热度在这个场景里的权重不是最高的。

跑完测试之后，总体的感受是，元宝搜索的强项有三点：权威性、时效性、提供完整正文。

权威性能让政府网、统计局、卫健委等信息来源权重靠前，让模型获得第一手信息。时效性能增加参数，获取最新的金融数据等准确信息。提供正文可以减少 agent 的 fetch，大幅提升效率，降低延迟减少 token 消耗。

对于国内的 Agent 开发者来说，这三点都能让开发变得更事半功倍。同时需要注意的是，它的结果和参数关系很大，要把参数开放给 Agent。同时针对生活服务、学术论文等场景可以考虑接入垂类的 API 作为配合。

### 接入和价格

元宝搜索支持三种接入方式。Skill 最轻，写提示词就行，不改代码；MCP 适合已经在用 MCP 的工具链；API 直调是把搜索做成产品原生能力。

价格方面按量计费：极速版 14 元每千次，标准版 20 元每千次，旗舰版 26 元每千次，旗舰版要企业申请。

注册后默认送 2000 次每月，活动期凭专属邀请码可以提到 6000 次每月。
