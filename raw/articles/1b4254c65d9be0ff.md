You can now stream generative UI from your [Chat SDK](https://chat-sdk.dev) agent with [json-render](https://json-render.dev).

With a typed catalog of components, the agent writes a JSON spec that json-render converts into a Chat SDK card. Each adapter then posts the card in its platform’s native format, such as Block Kit on Slack and Adaptive Cards on Teams.

The catalog covers tables, charts, buttons, and more, so there’s no separate tool to build and maintain for each message shape.

Stream a generated card into the thread when your agent is mentioned.

## [Copy link to heading](#stream-cards-as-the-model-writes)Stream cards as the model writes

streamCard posts the card once its root element has content and updates the message as new elements stream in. Edits go out at most once every 500 ms by default, which matches Chat SDK’s streaming interval. Once the stream ends, the message shows the final, validated card.

## [Copy link to heading](#validate-specs-and-enforce-platform-limits)Validate specs and enforce platform limits

toCard checks every element’s props against its component schema and throws CardSpecError for an invalid spec. Each problem gets its own readable issue, so you can send the list back to the model for a corrected spec.

Platforms cap what a single message can hold, and Chat SDK adapters degrade content past those caps. The Slack adapter, for example, turns a second table into a code block. Pass limits to reject those specs instead.

Read the [documentation](https://json-render.dev/docs/api/chat) to get started, or [try the playground](https://chat-sdk-demo.json-render.dev).
