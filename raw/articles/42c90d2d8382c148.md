在 AI 圈混，最容易得的就是「赛博工伤」。

最近这段时间，Claude、Codex、Gemini 轮着番地发新模型、推更新，每次一有动静就得连夜跟着测。工具一多，折腾的破事也跟着翻倍：Codex 最近被不少人吐槽难用、工作流里各种别扭，逼得大家满世界找替代；好不容易切回 Claude，又得面对永恒的生存难题——封号、重开、折腾网络环境

前两天我刚把 Claude 注册、订阅打通的帖子发出来，评论区直接问爆了——从邮箱收码、网络环境到支付订阅各种折腾，光看那几十条问答，就知道大伙为了把 AI 账号养活有多累

每天把精力全花在给模型调环境、给账号续命上，回过头一看：自己天天熬夜盯屏幕，久坐十几个小时，每年体检完的 PDF 报告往医院系统里一扔，连看都懒得点开第二次

-----

我突然有点好奇：如果把一个“重度折腾 AI 的打工人”这几年的体检单和熬夜记录全喂给大模型，AI 真能看懂我们的身体吗？

为了不暴露真实隐私，我直接用开源工具 mirobody-gen 生成了一套虚拟的跨年度健康数据——模拟了 2024 到 2026 连续三年在不同医院做的虚拟体检报告（故意让不同医院的指标叫法和单位不统一），在 Claude Code（模型：Claude Sonnet）里做了个前后对比：

1. 先把这些虚拟报告直接丢给普通大模型 我直接问：「帮我对比这三年体检单里血脂和尿酸的变化趋势，并列出下次去医院复查该问医生的问题。」 结果非常经典：因为不同医院模板里，同一项指标有的写全称「低密度脂蛋白胆固醇」、有的写缩写「LDL-C」，尿酸的单位有的用 μmol/L、有的用 mg/dL，大模型直接把它们当成了两项不相干的指标，各算各的，甚至漏掉了跨年上升趋势。

这也印证了 Theta Health（Mirobody 背后的团队）发表的评测研究 ESL-Bench（arXiv 2604.02834） 中的结论：直接把非结构化健康文档丢给传统检索方式，准确率只有 30%–38%；而先将数据标准化入库再由 Agent 查询，准确率能提升到 48%–58%。

2. 换个思路：给 Agent 接上 Mirobody MCP 再测一遍 不用部署后台，也不要 API Key，在终端直接用一条命令就能把 Mirobody 的本地 MCP 接进 Agent：

Claude Code 接入： claude mcp add mirobody -- uvx --python 3.12 mirobody mcp （启动 Claude Code 后输入 /mcp 看到 mirobody 显示已连接即可验证）

Codex 接入： 同样使用 uvx --python 3.12 mirobody mcp（在终端执行 codex mcp add mirobody -- uvx --python 3.12 mirobody mcp 或写入 ~/.codex/config.toml 后即可调用）

接好之后，由 Claude Code 负责读取这三年的虚拟体检文件，并自动调用 Mirobody MCP 把指标名称和单位统一，再问同一个问题，画风完全变了：

跨医院指标与单位自动对齐：Mirobody 底层把不同医院的「低密度脂蛋白胆固醇 / LDL-C」映射到了同一个标准医学编码，并自动把不同报告里的 mg/dL 和 μmol/L 统一换算成同一单位，准确拉出了三年连续上升的趋势线（例如尿酸从 2024 年的 390 μmol/L 涨到 2026 年的 465 μmol/L）

每个数字都带出处：输出的趋势总结里，每一个数值都标明了来自哪一年的哪份虚拟报告，不会凭空编造

生成就医提问清单：AI 没有越界下医疗诊断，而是根据这几年的异常波动，帮我整理了一份「下次看医生最该问的 4 个问题」（比如是否需要复查肾功能、饮食调整观察周期等）

(注：接入 Claude Code、Codex 这类云端工具时，对话记录会发给对应的模型公司；如果你对隐私特别敏感，Mirobody 也支持 100% 本地部署，数据完全不离开自己电脑。)

测完这一圈我其实挺有感触的

模型每周都在更迭，Codex 今天难用大不了换个工具，Claude 账号封了也能再重新折腾一个；但我们自己和爸妈每年的体检 PDF、医院拍照化验单、手环睡眠记录，散落在各个医院系统和微信聊天记录里，今天不存下来，以后再强的 AI 也补不回来

Mirobody 是 Theta Health 开源的 AI 健康数据引擎（Apache-2.0 协议）。除了能接 Claude Code、Codex、Cursor、Gemini CLI 这些 Agent 工具外，开源版还自带「家人档案」功能，能帮不怎么用手机的长辈把历年体检单统一管起来，查看和编辑权限全掌握在自己手里
