# Build a Chatbot

The DeepSeek API offers the same conversation features as DeepSeek Chat on the web and in the app: web search, deep thinking search, file input and URL reading, plus basic risk control for model content safety. You can use them to build your own chatbot.

The service runs the searches and URL reading. Your client only shows the returned blocks and passes them back unchanged in the next round.

## Feature Map[​](#feature-map)

Chatbot featureDescriptionGuide
Web search
With thinking disabled and the deepseek_web_search tool enabled, the model runs web or image searches as the question requires and answers with citations
[Web Search](/guides/web_tools#web-search)

Deep thinking search
With thinking enabled and the deepseek_web_search tool enabled, the model searches the web and reads links on its own over multiple reasoning steps
[Deep Thinking Search](/guides/web_tools#search-while-thinking)

File input
Upload files such as PDF, Word, PowerPoint and image files; after plain-text extraction or rich-layout parsing, they are added to the conversation context for the model to answer from
[File Parsing](/guides/document_parsing)

URL reading
With the deepseek_read_url tool enabled, the model detects links in the user message, fetches the pages and answers with them in context
[URL Reading](/guides/web_tools#read-links)

Model content safety
With the safety check parameter enabled, we provide basic risk control: the model input and output are reviewed, and a refusal marker is returned when a risk is found. If you provide a service to the public, enable this parameter and fulfill obligations such as content safety review, large model registration and AI labeling
[Model Content Safety](/guides/safety)

User metadata marker
Tell the model the current date and the user's location and language, so that answers fit the user's situation
[User Metadata Marker](/guides/latest_reminder)

Conversation title
Generates a short title from the conversation when the answer ends
[Conversation Title](/guides/conversation_title)

Read aloud
Turns the model's answer into speech
[Text to Speech](/guides/tts)

Voice input
Transcribes the user's speech into text to send as a message
[Speech to Text](/guides/asr)

## Demo[​](#demo)

DeepSeek provides an open-source demo chat client that shows how to build a chatbot with these APIs. Enter your API key to start. You can also import the chat history you exported from DeepSeek Chat and continue your conversations.

- Try the demo: [https://cdn.deepseek.com/chat-demo](https://cdn.deepseek.com/chat-demo)

- Source code: [https://github.com/deepseek-ai/chat-demo](https://github.com/deepseek-ai/chat-demo)

Your API key, conversations and uploaded images are stored only in your browser. The demo is for demonstration only.

The demo shows:

- Web search, deep thinking search and URL reading

- Uploading images and documents

- Model content safety, including image review

- Conversation titles, and renaming and deleting conversations

- Editing a message, regenerating, and continuing a reply

- Reading answers aloud, and voice input

- Choosing a language and location in the settings, which are passed to the model as the user metadata marker

- Importing and exporting chat history (an import replaces the existing history)

- Markdown rendering, including Mermaid diagrams

- A Chinese and English interface, with light and dark themes

## Choose a Protocol[​](#choose-a-protocol)

The chat features are available in the Messages API, the Responses API and the Chat Completions API.

ProtocolEndpoint
Messages
POST https://api.deepseek.com/anthropic/v1/messages

Responses
POST https://api.deepseek.com/responses

Chat Completions
POST https://api.deepseek.com/chat/completions

Use the deepseek-flash model.

## Render a Response[​](#render-a-response)

A chatbot response contains several kinds of content blocks. The screenshot below marks where each block appears in DeepSeek Chat.

BlockWhat to show
thinking
The collapsible thinking panel

server_tool_use + web_search_tool_result
A search step with result cards (title, site name, icon)

server_tool_use + web_fetch_tool_result
A page that was opened or a link that was read

text with citations
The answer, with citation markers that link to the sources

stop_reason: "refusal"
Replace the answer with your refusal message

See [Web Tools](/guides/web_tools#response-blocks) and [Model Content Safety](/guides/safety#handling-refusals) for the block formats.

## Ignored Parameters[​](#ignored-parameters)

When a request declares deepseek_web_search or deepseek_read_url, sets safety_check to high, or enables title, the service decides the following parameters, and the values in the request are ignored:

ProtocolIgnored parameters
Messages
temperature, top_p, top_k, stop_sequences, thinking.budget_tokens, preserve_thinking, tool_choice.disable_parallel_tool_use, metadata (except user_id)

Responses
temperature, top_p, reasoning.summary, text.verbosity, include, max_tool_calls, truncation, metadata, parallel_tool_calls, store

Chat Completions
temperature, top_p, frequency_penalty, presence_penalty, stop, seed, n, preserve_thinking, parallel_tool_calls

max_tokens (max_output_tokens in the Responses API) works as usual. It limits the output of each inference step in a round, not the total output of the round.

## Compliance Requirements[​](#compliance)

- With the safety check parameter enabled, we provide basic risk control: the model input and output are reviewed, and a refusal is returned when a risk is detected. If you provide a service to the public, enable this parameter, and fulfill on your own the obligations of a service provider, such as content safety review, large model registration and AI labeling.

- Please comply with our Open Platform Terms of Service: [DeepSeek Open Platform Terms of Service](https://cdn.deepseek.com/policies/en-US/deepseek-open-platform-terms-of-service.html).
