Anthropic 团队 Eugene Yan 深度拆解「12 项 AI Evals」：分数之外，怎样判断 Agent 真能交付？

Agent 得分越来越高，为什么上线后仍要人反复检查？Eugene Yan 这篇深度长文拆解了 12 项公开评估，覆盖编程、科学、知识工作、浏览与电脑操作，追问任务怎样构建、评分哪里失真，以及生产环境真正该测什么。

# 先看任务怎么出，评分怎么判

一次评估通常包含指令、执行环境、评分器，以及可选的专家参考成果。许多基准优先用代码检查最终状态，必要时才让模型逐项判断是否达标。

这有利于复现，却不保证评分正确。作者梳理的 12 项评估中，8 项存在评分器误拒有效成果的审计或问题报告；这不能当作所有基准的错误率。

不如 Epoch AI 审查 DeepSWE v1.1，在 113 项任务中确认至少 23 项存在假阴性，其中 18 项涉及 Agent 的测试与隐藏测试冲突。认真补测试，反而可能让评分过程编译失败。要求所有检查通过时，一个坏检查就能让整项任务归零。

反过来，逐项达标也可能漏掉严重错误。Artificial Analysis 在 Harvey 法律任务实验中发现，原本通过全部评分条件的结果里，超过 60% 仍含实质性幻觉。

# 同样 70%，可靠性可能完全不同

一个 Agent 稳定解决七成任务，另一个对每道题都有七成成功概率，平均分都可能是 70%，使用体验却不同。

Eugene 建议补充 τ-bench 推广的 pass^k：同一任务重复运行 k 次，必须次次通过才算成功。

假设第二种 Agent 每次独立、成功概率固定为 70%，五次全对只剩约 17%；第一种仍是 70%。这是解释指标的假设例子，不是实测成绩，也不同于“多试几次、成功一次即可”。

# 成本要把人的返工算进去

提前放弃、跳过验证，都能让一次运行显得便宜。Eugene 引用的 AutomationBench 分析显示，在失败案例中，模型仍宣称成功的比例达到 72%—91%。无法辨别哪些失败，就得检查全部输出。

GDPval 的情景估算也显示，加入专家审阅和重做后，GPT-4o 可能比专家独立完成更慢。这依赖成本模型假设，并非真实企业生产率实验，但提醒我们关注：完成一份可用成果，究竟需要多少人工投入？

# 还要测追问、取舍与真实运行框架

为了便于验证，一些任务把开放需求改成明确规格，测到了执行能力，却弱化了“该做什么、哪些不该做”的判断。

现实协作还包含追问、需求变化和中途纠偏。OSWorld 2.0 已加入模拟用户与途中消息，但单次下发完整需求仍很常见。

分数也受系统提示、工具、上下文压缩和重试预算影响，代表的是模型与运行框架的组合。
