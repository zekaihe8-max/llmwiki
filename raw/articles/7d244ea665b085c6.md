When you have Claude Code build a feature, everyone has it write a design doc first. The problem is that 𝗻𝗲𝗶𝘁𝗵𝗲𝗿 𝘆𝗼𝘂 𝗻𝗼𝗿 𝗖𝗹𝗮𝘂𝗱𝗲 𝗰𝗮𝗻 𝘀𝗲𝗲 𝘄𝗵𝗲𝗿𝗲 𝘁𝗵𝗲 𝗱𝗼𝗰 𝗶𝘀 𝘃𝗮𝗴𝘂𝗲, because you both already know what you meant.

What thousands of engineers at one big tech company do every day: spawn a subagent that has seen nothing, give it only the doc, and have it explain the plan back. Wherever it gets the plan wrong, the doc is vague.

When you spawn it, say "don't fork." Claude Code has fork mode on by default, and 𝗖𝗹𝗮𝘂𝗱𝗲 𝗰𝗮𝗻 𝗱𝗲𝗰𝗶𝗱𝗲 𝘁𝗼 𝗳𝗼𝗿𝗸 𝗼𝗻 𝗶𝘁𝘀 𝗼𝘄𝗻. A forked subagent carries your whole conversation with Claude, so of course it explains the plan back perfectly, and you walk away thinking the doc is fine.

Send this to Claude Code before any code gets written, and catch the gaps in your doc in one pass 👇

"Spawn a new subagent, not a fork. Give it only the path to design.md, no summary. Have it:
1. Write two paragraphs in its own words (2-5 sentences each): what this doc proposes, and how the existing system works according to the doc.
2. Mark any part it can't explain back as a blocker.
3. List project-specific terms the doc never defines or links to, and setup steps the doc assumes the reader already knows but never writes down.
It's read-only and changes no files. Compare its version with the plan we agreed on. Wherever they don't match, fix the doc first, then write the code."
