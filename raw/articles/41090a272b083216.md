DeepSeek Harness 优化小技巧，可以试试从 AGENTS.md 和 CLAUDE.md 这两个文件入手优化🔥

上一篇分享了我最近使用 DSH 的一些问题，这次翻了一下官方文档，发现有个地方挺值得折腾，就是通过项目指令来约束 Agent 的工作方式，尽量减少无效的 Token 消耗

如果再配合上极简模式，就可以把你的 DeepSeek harness 打造得跟 PI agent 一样简洁干净

1、先搞清楚 AGENTS.md 和 CLAUDE.md 怎么用

DSH 默认会自动读取这两种文件，并把对应规则加入 Context

① 全局规则：~/.dsh/AGENTS.md

② 项目规则：项目目录下的 AGENTS.md 或 CLAUDE.md

③ 子目录规则：可以单独放在对应模块下，按目录作用范围加载

这里有个容易忽略的地方，DSH 并不是只读取其中一个文件

如果同目录下两个文件内容不同，就可能同时加载，只有内容相同才会去重

所以我更建议把 AGENTS.md 作为主要规则来源，CLAUDE.md 尽量复用同一份内容，不要重复写两套规范

2、真正要优化的是 Agent 的执行规则

我觉得没必要往里面塞一大堆角色设定，反而应该把实际使用中遇到的问题写清楚

比如可以加入这几条：

① 收到明确任务后直接执行，避免反复解释计划

② 优先读取相关文件，不要无意义地扫描整个项目

③ 修改代码时控制范围，不要顺手重构无关内容

④ 验证以任务要求为准，通过后及时结束，不要反复截图、自检和修改

⑤ 工具报错先分析原因，避免使用相同参数无意义重试

对于复杂的部署、Review、测试流程，可以拆成独立 Skills，需要的时候再加载，没必要每轮都带着完整说明

这也只是我自己尝试得到的效果，你也可以通过创造模式设置你自己喜欢的方式，我现在都在想 我是不是把 PI 的默认系统提示词放到 DeepSeek harness 上去玩一玩

不知道会不会把 DSH，打造的和 PI agent 也好用，有时间我再重新测试一下，发现好玩的第一时间分享出来给大家
