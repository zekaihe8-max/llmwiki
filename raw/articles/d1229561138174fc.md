Pi 1.5.1 正式发布！这次更新有几个变化，我觉得值得关注 🔥

Pi 最近的更新速度还是挺快的，这次 1.5.1 没有增加什么大功能，主要是优化日常使用体验，修复了一批问题，同时也调整了部分默认行为

我看了一下完整的更新日志，整理了 5 个比较值得关注的变化

1、终于可以直接通过命令行登录了

以前需要进入 Pi 会话，再通过 /login 和 /logout 操作

现在直接在终端执行 pi auth login <provider> 就可以登录，退出则使用 pi auth logout <provider>

还支持 --api-key 和 --no-browser，使用起来方便了不少

2、缓存保温的默认策略变了

以前 cacheWarming 默认是 streaming，现在改成了 idle

符合条件的 Prompt Cache 可以在两次运行之间保温最多 30 分钟，而且会判断刷新缓存是否划算，避免不必要的消耗

如果习惯之前的行为，也可以手动切回 streaming

3、Anthropic 支持 Message Threads

这个我觉得是本次比较值得关注的更新

Pi 现在默认在 Anthropic 官方 API 上启用 Message Threads，不需要每次请求都重新发送整段历史对话，而是只发送新增消息

如果发生上下文压缩、工具列表变化等情况，还是会退回完整请求

4、默认模型迎来一轮更新

这次多个 Provider 的默认模型都发生了变化

比如 Anthropic 换成 Claude Opus 5.5，Azure 换成 GPT-6.1 Sol，Google 换成 Gemini 4 Argon

OpenCode Go 则换成 Kimi K3.1 Pro，部分其他提供方更新到了 Kimi K2.7 Code

整体来看，Pi 也在持续跟进各家最新的模型

5、两处兼容性变化需要留意

如果你平时会自己开发 Pi Extension，或者接入 vLLM、LiteLLM，这部分建议看一下

一处是 GrepOperations.readFile 不再负责读取 grep 的上下文行，远程搜索需要调整实现方式

另一处是 OpenAI-compatible 请求在没有可用工具时，不再发送空的 tools: []，而是直接省略这个字段，解决部分服务的 400 报错

这次还有不少其他修复，包括大文件读取内存占用、OAuth 刷新、grep 路径匹配以及 Mermaid 渲染等

整体来说，Pi 1.5.1 更像是一次日常体验的打磨，尤其是命令行登录、缓存策略和 Anthropic 请求优化，对长期使用 Pi 的人来说都比较实用
