DeepSeek Harness 已经有 3.5 万个插件了，但我反而开始担心它的稳定性🔥

前几天官方公布了一组数据，DSH 已经达到 154 万日活，第三方插件约 3.5 万个，60% 的活跃用户创建或者安装过插件

这个成绩确实不错，但是我在 GitHub 反馈当中发现，插件兼容性的问题也越来越值得关注了

甚至有用户从 0.2.1-rc.5 升级到 0.2.2-rc.1 之后，原本配置的 34 个插件 Bundle 只剩下 2 个，最后花了差不多 5 个小时才恢复

还有一些插件因为底层接口变化无法正常使用，甚至影响到对话和定时任务

我觉得 DSH 接下来需要重点解决三个问题：

1、插件 API 的稳定性

不能每次更新都让开发者重新适配，尤其是一些已经被广泛使用的接口

最好能够提供一定的兼容期，升级之前先检测插件是否支持新版本，不兼容就明确提醒用户

2、插件后续无人维护的问题

3.5 万个插件确实很多，但不是每个开发者都有时间长期维护

如果作者停止更新，而 DSH 又不断升级，最终可能出现插件还在市场里，却已经无法使用的情况

我觉得官方插件市场应该展示插件的兼容版本、最后更新时间和维护状态，让用户知道哪些插件真正能用

3、升级和回滚机制

这一点我专门去 GitHub 社区找了一下，发现已经有人分享了一些处理方案

比如在 Web/CLI 环境中，提前建立一个不安装第三方插件的备用 Profile，主环境崩溃之后，可以通过备用环境修复配置

还有开发者做了一个叫 dsh-plugin-health 的工具，能够检查插件版本兼容性，并尝试在临时环境中验证插件能否启动

项目：[github.com/EasonMWS/dsh-p…](https://t.co/fgbEcY02Dv)

当然，这些都只是现阶段的补救措施，不能保证所有插件都能修复

官方最近也开始支持插件更新失败后尝试恢复旧版本，但我觉得还需要更完善的升级前备份、兼容性检查和一键回滚

其实我一直觉得，DeepSeek Harness 的 Everything is a Plugin 理念很有潜力

但是插件生态不能只看数量

如果安装了几十个插件，每次更新都要担心哪些会失效，甚至需要花几个小时去修复环境，那整体体验反而会越来越差

真正成熟的 Agent 插件生态，不是有多少人开发插件，而是这些插件过了半年、一年之后，还能不能稳定使用
