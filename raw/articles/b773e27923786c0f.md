[@trychroma](/trychroma) CEO [@jeffreyhuber](/jeffreyhuber) - Chroma 已经被 Replit 收购
CMPND CEO [@dbreunig](/dbreunig) - Context Engineering Handbook 作者

为什么要学
Agent 跑得越久，上下文越容易塞满重复、矛盾、过时的信息。模型在长上下文上表现会变差，Jeff Huber 与 Chroma 团队把这类现象叫做 Context Rot。更大窗口治不好，单纯改提示也治不好；要修的是上下文本身：在合适时机，以合适格式，放进真正相关的信息。

你会练到的三条能力
· Agentic Search：多工具、多源取数；用 trace 改进工具选择，并用评估闭环。
· Context Management：用剪枝、压缩、草稿本整理任务所需信息。
· Agentic Memory：把用户反馈等存成可复用记忆，任务需要时取回，跨会话按变化增改。

适合谁
做 AI Agent、希望复杂多步任务更稳、更省的人。预设：中级 Python（函数与类）、熟悉 LLM 应用、工具调用和基本检索。页面建议可先刷 [@DeepLearningAI](/DeepLearningAI) 的 Agentic AI、RAG 课作热身。

# 课程结构（四模块）

模块 1｜Context Engineering 导论
Andrew Ng 与 Jeff Huber 对谈开场。讲清上下文由什么组成、常见失效方式、什么是 Context Rot，以及如何用 harness 的 hooks 与 traces 发现并预防问题。实验包括：上下文失效模式、拆解一个客服 Agent、动手塑造其上下文。Drew Breunig 第一段客座约 7 分钟。

模块 2｜Agentic Search
以编码 Agent 为例。覆盖词法、语义、混合与结构化检索；写好工具描述、用 tool registry 按需加载工具；用切块、代码解析、元数据改进检索，并用精确率 / 召回率衡量。含搭建搜索系统、工具注册表等实验；Drew 第二段客座约 5 分钟。

模块 3｜Context Management
以研究类 Agent 为例。先看清上下文窗口里有什么，再练 pruning（去重、抽取、截断等 hooks）、compaction（把长历史压成结构化摘要）、scratchpads（把全文与任务状态挪到窗口外）。对比「开 / 关」各操作前后的跑次差异，并做上下文管理评估。Drew 第三段客座约 4 分钟。

模块 4｜Agentic Memory
以邮件 Agent 为例。区分事实、规则、产物等可跨会话的记忆记录；决定每条新信息是新增、更新还是跳过；评估记忆是否真的让用户少重复交代。读写记忆各有实验；Drew 第四段客座较长（约 17 分钟），随后结课。

各模块均有分级作业与可选材料；实验多为约 1 小时量级的代码练习（页面标注）。
