Nobody warns Claude Code users about this part.

Simply put, you ask Claude to add a column or build an index on a table with tens of millions of rows. The migration runs, 𝘁𝗵𝗲 𝘄𝗵𝗼𝗹𝗲 𝘁𝗮𝗯𝗹𝗲 𝗴𝗲𝘁𝘀 𝗹𝗼𝗰𝗸𝗲𝗱, and your live app freezes with it.

Install a subagent that only handles databases. Every time you change the database, it:
- reads your existing schema and past migrations first
- flags changes that would lock tables or break your live app
- rewrites them so nothing gets locked and your app keeps running through the deploy
- runs the migration on a temporary database before handing it back

The person who rewrote this subagent tested it: an 80M-row table, 10 minutes before deploy. Same prompt: 𝟲/𝟭𝟬 𝘄𝗶𝘁𝗵𝗼𝘂𝘁 𝗶𝘁, 𝟭𝟬/𝟭𝟬 𝘄𝗶𝘁𝗵 𝗶𝘁. In 8 tests, Claude called it on its own all 8 times.

One command to install 👇
npx claude-code-templates@latest --agent database/database-architect
