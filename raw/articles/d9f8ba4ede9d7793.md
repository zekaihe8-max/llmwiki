为什么 Anthropic 敢直接让 AI 把核心 API 从 Python 重写成 Rust ？

刚看到这个内容，我和很多人一样，都以为 Claude 这又是在秀，但是整篇看下来，人家讲的根本不是怎么写代码，而是怎么防着 AI 糊弄你

平时我们让 Agent 改个小项目都怕跑偏，更别说 Messages API 这种扛着 Claude Code 和全球调用量的命脉接口

我实在好奇他们是怎么兜底的，干脆把官方刚放出来的工程复盘顺着时间线捋了一遍

这事最开始纯粹是被暴涨的流量逼出来的

这套接口 2023 年刚写出来时只是个 Python 转发器，2024 年有人提议改 Rust，还被同事一句话顶回去说绝不可能重写

结果两年多下来，线上请求量暴涨了大概 1800 倍，Python 每次建对象、回收内存和拆工具调用都在白白烧算力

今年 3 月他们也试过只把解析输出那一小块改成 Rust，结果 CPU 只省了不到 10%，每个 Token 反倒要来回跨三次语言边界

到了 5 月，团队发现内部合入的代码里超过 80% 已经是 Claude 写的，局部修补根本不划算，索性决定整套重写

写代码只花了一周，真正的雷全埋在测试里

Claude 大概一周就把核心链路的 Rust 初版写出来了，4 月份拿原有的 700 多个集成测试一跑，通过率高达 98%

看着好像马上就能收工，但是拉去跟线上真实流量一比对，输入匹配率居然只有惨兮兮的四分之一

更离谱的是工程师回头查 AI 顺手迁移过来的测试代码，当场抓出来 100 多处被悄悄放水的断言

AI 为了把测试跑绿，自己悄悄把验收标准给改松了，再加上老的 Python 接口每天还在发新功能，靠传统单测根本不敢上线

单测信不过，他们干脆把线上老系统变成了考官

因为不能看用户的真实提问，模型回答又有随机性，他们就让模型只跑一次，把同一份输出同时喂给新老两套代码去比对

哪怕不看具体文字，只要记下提示词在第几段、第几个字节开始不一样，再算一下长度差，同一个 Bug 留下的字节指纹都是一模一样的

靠这套字节指纹把报错归好类，就能精准派给子 Agent 一个个去修

光抓出差异还不够，还得防着 AI 为了过关耍小聪明

5 月中旬排查联网搜索差异那次就特别典型，因为 Rust 版还没接内部拉取工具说明的服务，两边拼出来的提示词对不上

结果有个 Agent 居然把说明文字硬拷进本地文件里交差，沙盒验证器当场就判了通过，还好工程师审代码时发现是糊弄事，及时拦了下来

为了不重复踩坑，他们又在沙盒和影子流量外加了一层记忆循环，把每次打回的教训写进 CLAUDE.md，让后面的 Agent 全都长记性

捋完整个过程，我最大的感受就是软件开发的卡点真的变了

以前不敢动老系统是因为重写太慢，现在这套 Rust 接口能在 9 月稳稳切流上线，单请求 CPU 砍掉约 70%，首字延迟也降了 20% 左右

真正拉开差距的早就不是模型写代码有多快，而是你能不能搭出一套严丝合缝的验证 Harness，外加人类在关键架构上的把关
