Pi 1.5.1 更新之后，有 4 个使用技巧值得了解，部分操作和旧版本区别挺大！🔥

这次更新有一个很容易被忽略的变化：即使你没有继续和 Pi 对话，它也可能在后台刷新 Prompt Cache，产生一定的费用

除了缓存，我还整理了几个和旧版本操作不同的地方，尤其是经常使用 Pi 的开发者，可以看一下

1、缓存保温默认策略变了

以前 cacheWarming 默认是 streaming，现在改成了 idle

Pi 在空闲时也可以自动保温缓存，最长 30 分钟，但会先判断刷新是否划算

可以在 Pi 中执行 /session 查看缓存保温状态

如果想恢复旧版行为，在 ~/.pi/agent/settings.json 添加：

"cacheWarming": "streaming"

如果不需要自动保温，可以直接改成 "off"

2、登录模型不需要进入 Pi 会话了

以前需要先启动 Pi，再输入 /login

现在直接在终端执行：

pi auth login anthropic

如果在没有浏览器的服务器上，可以加上 --no-browser，通过授权码完成登录

退出则使用 pi auth logout anthropic

对于经常在 VPS 上运行 Pi 的人来说，这个改动还是挺方便的

3、Anthropic 不再每次重发完整对话

新版默认在 Anthropic 官方 API 上启用 Message Threads，连续对话时只需要发送新增消息

不过，如果发生上下文压缩或者工具列表变化，仍然会回退到完整请求

如果使用第三方 API 网关，需要确认是否支持 thread 字段

不支持的话，可以在 models.json 对应模型的 compat 配置里设置：

"supportsMessageThreads": false

4、终端界面不习惯，可以切回旧版

Pi 从 1.5.0 开始默认使用 fullscreen 模式

如果你更喜欢以前的终端滚动方式，可以执行：

pi --tui-mode regular

也可以在 settings.json 中设置 "tuiMode": "regular"，以后就不用每次手动切换了

另外，这次的 pi update --extensions 也更实用了，可以直接看到插件更新前后的 npm 版本或 Git commit 变化

这几个地方不用全部修改，主要看自己的使用环境

我觉得最需要检查的还是缓存设置，尤其是平时经常开着 Pi，但并不一直使用的人，可以看看默认策略是否适合自己
