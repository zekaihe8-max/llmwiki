Lauren Tan 更新开源 Skills pstack：新增 /reframe skill，先补齐 8—12 个专业概念，再把模糊想法改写成清晰需求

Grok Bot 成员 Lauren Tan（[@poteto](/poteto)），给自己的开源 Skills 集合 pstack 加入了 /reframe。它针对的是开发里很常见的一个卡点：心里清楚大概想做什么，却缺少准确表达需求的专业概念。她的出发点是，你能向模型提出什么要求，很大程度上取决于你能想到、也能说清什么。

pstack 本身是一套面向 Coding Agent 的工程工作流与 Skills 说明，主打少写代码、提高工程质量；这次更新把重心往前挪了一步，先解决需求进入开发之前的表达问题。

# 从原始材料里找准问题，再教你术语

/reframe 要求模型直接读取用户的原始文件、代码和描述，避免靠二手摘要猜问题。如果一句需求可以按好几种方向理解，它会先摆出两三种解释，讲清各自叫什么、靠什么信号区分，再说明为什么选定其中一种。

定好问题后，它会列出 8—12 个关键术语，按“会多大程度改变最终成品”从高到低排序。每个词都会讲清楚含义、对应需求里的哪一块、附上真实项目或论文链接，并告诉你掌握这个词后该怎么向智能体提要求。

接着它还会借用两三个相邻领域的经验，指出哪些做法能直接拿来用、类比在什么地方会失效，最后补全用户容易漏掉的约束条件并重写需求。规则里还明确要求逐条打开链接核对用法，查不实的引用直接删掉。

# 和 /sharpen 分别解决什么

两个 Skill 分工清楚：/reframe.负责把概念和表达补齐，/sharpen 则负责把任务要求做深，追问这个领域的顶尖从业者会多做哪几步、应该从哪些一手材料出发、采用什么方法，以及靠什么外部证据来验收结果。

在当前公开版本里，/sharpen 会重写提示词，并把决策分成两类：能靠小实验验证的技术选型，先做原型观察结果再给建议；无法靠实验定夺的产品取舍和个人偏好，则留给用户决定。这两个 Skills 都设为手动触发，适合先用 /reframe 厘清概念，再用 /sharpen 敲定做法和验收标准。

## 我的看法

这次更新最有价值的地方，是把“帮用户把需求想清楚”拆成了可执行的步骤。开发里很多返工，源头都在最初的需求还停留在模糊直觉；一旦补上准确的专业术语，既能直接带出成熟方案，也能提前暴露漏掉的边界条件。不过，术语筛选和引用核查目前依然由模型完成，公开材料里也没有效果评测数据，实际价值还得看重写后的需求能否真正减少歧义和返工。
