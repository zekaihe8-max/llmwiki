Armin Ronacher AI Engineer 演讲：启动 141 个项目之后，为什么 Agent Coding 更该追求软件质量 ？

Flask 作者、Earendil (Pi Agent 团队) CTO Armin Ronacher 在 [@aiDotEngineer](/aiDotEngineer) 演讲中提出：先建好软件工作坊，再考虑软件工厂。Agent 应该帮助我们挑战更有野心、更高质量的软件，不能只用来扩大产量。
[youtube.com/watch?v=JNexz3…](https://t.co/RR9MLTktn8)

# 模型进步了，人的注意力没有

他的 Pi 核心工具集近一年基本稳定，但随着模型升级，每 100 次提示对应的纠正和按 Esc 中止次数明显下降，分别从早期的 8.5 次和 13.1 次降到 3.9 次和 7.2 次。个人会话里，单次任务运行时长的 P90 也从约 2.5 分钟拉长到 14 分钟以上。这记录的是他本人的使用变化，不能直接等同于任务成功率提升。

另一张图更有冲击力：他累计启动了 141 个项目，但按月统计、当月投入至少 5 天的项目始终只有个位数到十来个。创建仓库越来越便宜，持续使用、理解和维护它们，依旧消耗人的注意力。

# 工程师要知道什么时候说“不”

Agent 完成局部目标，不保证产品整体协调。不断接受功能和补丁，内部复杂度会迅速膨胀；熟练使用 Agent，也替代不了识别坏设计的工程判断。

他的做法是在最终验证前，让 Agent 先给出一份简短摘要和易读的 HTML 页面，给自己留出理解与纠偏的窗口。与此同时，开放协议、文件格式和上游协作依然重要。各自重写一套实现很快，让不同实现长期兼容，仍需要人与人达成共识。

# 长任务需要更扎实的运行系统

他没有否定 Harness 的价值。任务从几分钟变成整夜批处理，运行系统就需要支持暂停、恢复和失败后继续；等待低价推理资源时，也该避免沙箱空转。

另一个方向是 Code Mode：让 Agent 编写 JavaScript 编排工具调用，先在代码里处理中间结果，再把必要信息送回模型上下文，重复分支还可以交给快速分类模型处理。不过在持久化、小模型适配和二进制数据处理上，这套路线仍有不少难题，远没到全自动的阶段。
