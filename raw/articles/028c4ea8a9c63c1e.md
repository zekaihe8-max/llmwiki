为什么越来越多开发者开始放弃 Claude Code，转向 Pi Agent🔥

最近一篇《Goodbye Claude, Hello Pi》在 Hacker News 上引起了很大的讨论，获得了数百条评论

作者使用 Claude Code 已经一年多了，最终决定把自己的主力 Coding Agent 换成 Pi

我觉得其中有两个观点，我觉得很值得聊一下

1、功能越来越多，但是不代表体验越来越好

作者统计了一下，截至今年 9 月，Claude Code 已经发布了 244 个版本，其中超过 75% 修改过 System Prompt 或工具描述

这其实是一个很有意思的问题

对于长期使用 Coding Agent 的开发者来说，最重要的不一定是不断增加新功能，而是自己已经搭建好的工作流能够稳定运行

比如作者在 VS Code 里同时运行多个 Claude Code 会话时，只有一个会话能够接收编辑器的选中文本，这个问题一直影响他的日常使用

在我看来，Coding Agent 和普通软件不太一样，System Prompt、工具调用逻辑的变化，都可能影响最终执行结果

如果每次更新都需要重新适应，反而增加了使用成本

2、Pi 最大的优势，是把控制权交还给开发者

作者换成 Pi 之后，只用了大约 20 分钟，就通过 Extension 解决了之前困扰自己的多会话问题

这也是我一直比较喜欢 Pi 的地方

Pi 本身足够精简，很多功能不会强制加入核心，而是交给开发者通过 Extension、SDK 自行实现

Hacker News 评论区还有一个很有意思的观点

有开发者表示，自己不希望 Claude Code 自动决定什么时候启动 Subagent、什么时候使用 Worktree，因为一旦 Agent 自己陷入循环或者产生合并冲突，反而需要花更多时间收拾

换成 Pi 之后，他可以自己决定这些功能怎么用，甚至不安装任何 Extension

这其实也是我之前一直在分享 Pi 生态的原因

对于普通用户来说，开箱即用可能更重要，但对于希望自己搭建 Agent 系统的开发者来说，能够控制工具、上下文和执行流程，反而更有吸引力

当然，评论区也有不少反对的声音

有人觉得 Pi 缺少默认的安全审批机制，第三方 Extension 还需要自己审核，最后又重新回到了 Claude Code

这个问题确实存在，Pi 的自由度越高，也意味着开发者需要承担更多配置和维护成本

所以我并不觉得 Pi 一定比 Claude Code 更好

两者最大的区别，可能是 Claude Code 希望把一套完整的 Coding Agent 交给你，而 Pi 更希望让你决定自己的 Agent 应该是什么样子

对于我这种喜欢折腾 Agent、自己开发扩展的人来说，后者显然更有吸引力
