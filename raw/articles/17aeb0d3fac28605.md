# Deepseek Harness 保姆级教程：从读第一份文件，到做一个结合 Grok Bot 读评论找选题的小插件

12 min read

如果你用过 DeepSeek 网页或 App，大概见过聊天框里的「深度思考」。2025 年 1 月，深度求索发布了推理模型 [DeepSeek-R1](https://api-docs.deepseek.com/zh-cn/news/news250120/)，当时打开这个开关，就能让 R1 把一道难题拆开来想。到了同年 12 月，[DeepSeek-V3.2](https://api-docs.deepseek.com/zh-cn/news/news251201/) 又多了一项本领：它可以一边推理，一边调用工具，拿到结果再决定下一步。

模型能判断「我得先看一眼文件」，可谁来把文件打开，把内容交给它？这就是 DeepSeek Harness 的用处。2026 年，深度求索先把这套连接模型和工具的工作环境[开放给开发者试用](https://www.deepseek.com/harness/zh/)，后来又推出了 [Mac 和 Windows 桌面端](https://www.deepseek.com/harness/)。现在，打开桌面应用就能选文件夹、看模型做了哪些修改，也能给它装插件，添上自己常用的功能。

### 01｜先分清：模型、Harness、工作区

平时我把一段话贴到 DeepSeek 聊天网页里，让它改个标题。换成这次的任务，我想说的是：「原稿在这个文件夹里，读一下。结果另存一份，原稿别动。」

这里分了三件事：模型读懂材料，决定怎么改；Harness 提供读写文件等工具，也负责给你看它做过什么；工作区就是你选给它干活的那个文件夹。文件在本机，用在线模型分析时，参与分析的内容仍会发给模型服务。第一次练手，找两行公开素材就行。

[/0xlangeai/article/2120769549679386878/media/2120747441003941888](/0xlangeai/article/2120769549679386878/media/2120747441003941888)

白纸是原稿，黄卡是结果。打开同一个文件夹，两份都在。

把这三件事对到界面上，就容易找入口了。下面是本机 Web 版的实际首页，桌面版也能按这些入口找。

[/0xlangeai/article/2120769549679386878/media/2120747441041596416](/0xlangeai/article/2120769549679386878/media/2120747441041596416)

- 左侧导航：点「新会话」开始一件事；「插件」用来安装、启用扩展；「自动化任务」管理定时任务。设置在左下角「更多」里。
- 左侧工作区和会话列表：文件夹对应工作区，下面挂着这个工作区的会话。后面读素材、存选题卡，都先确认选中了哪个文件夹。
- 中间会话区：发出任务后，这里显示你的要求、模型回复和读写文件等执行记录。新会话还没开始时，就先显示欢迎语和输入框。
- 输入框及周围控件：上方选工作区和「标准模式」等 Agent 模式；左下角「工作区内修改」管理这次任务的访问权限；右下角选模型。输入 / 调技能，输入 @ 引用文件或对话。

右侧是文件查看区。 上图是后文选题插件的实测结果：左边保留会话，右边打开生成的 Markdown。点击会话中的文件链接，就能查看内容；右侧栏收起来时，可以从右上角展开。任务跑完，我会在这里对照原要求，核对它到底写了什么。

下面就从这两份文件练起：先装好 Harness，让它读原稿、另存一张卡，再用现成的插件把卡片排成网页。等这几步走通，我们再做自己的选题插件：让 Grok Bot 从热帖评论里筛出有内容的回复，交给 Harness 里的模型判断，哪条读者提问值得单独写一篇。

### 02｜安装 Harness：桌面版，或安装 dsh 启动 Web 版

桌面版最省事。 到 [DeepSeek Harness 官网](https://www.deepseek.com/harness/)选「下载桌面端」。Windows 选 64 位版本；Mac 在苹果菜单的「关于本机」里看芯片，Apple M 系列选 Apple 芯片版。装好后打开 Harness，在欢迎页用自己的 DeepSeek 账号登录；手里已经有 [DeepSeek API Key](https://platform.deepseek.com/) 的，也可以选「添加 API Key」。能在新会话里选到模型，就可以往下走了。

想用本机 Web 版，就安装 dsh，也就是 DeepSeek Harness 的命令行程序。装好后，用 dsh web 启动服务，再从浏览器操作。下面按本文实测的 0.2.2-rc.1 版本走一遍。

第一步：装 Node.js，确认终端能找到它。 从 [Node.js 官网](https://nodejs.org/zh-cn/download)安装 24.9.0 或更高版本，npm 会一并安装。这是 [dsh 声明的运行要求](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/package.json)。装完重新打开终端：Mac 按 Command+空格 搜「终端」；Windows 在开始菜单搜「命令提示符」。逐行输入：

sh

```
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">node </span>-v
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">npm </span>-v
```

两条都能显示版本号，再往下走。node -v 如果还是旧版本，先检查刚装的 Node.js 是否已经生效。

第二步：安装 dsh，再核对版本。 在同一个终端执行：

sh

```
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">npm </span>install --global @deepseek-ai/dsh@<span style="--shiki-dark:#ffa359;--shiki-light:#d47628">0.2.2</span>-rc.1
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">dsh </span>--version
```

第一条会从 npm 下载并安装官方程序，等它执行完成，再运行第二条。看到 0.2.2-rc.1 就说明这次安装的 dsh 已经能用了。我这次实测用的也是这个版本。

第三步：启动 Web 界面。 接着输入：

sh

```
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">dsh </span>web
```

浏览器通常会自动打开。没有打开，就复制终端打印的完整访问地址，包括地址后面的参数；默认端口是 3080，实际以终端输出为准。服务运行期间留着这个终端。用完按 Ctrl+C 停止；下次重新打开终端，输入 dsh web 即可。[官方启动说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/README.zh.md#运行)

如果第二步提示 dsh 找不到，先重新打开终端再试。若全局安装报 EACCES 等目录权限错误，也可以改用下面这条命令，由 npx 获取同一版本并启动：

sh

```
<span style="--shiki-dark:#08c0ef;--shiki-light:#009fff">npx </span>@deepseek-ai/dsh@<span style="--shiki-dark:#ffa359;--shiki-light:#d47628">0.2.2</span>-rc.1 web
```

第一次询问是否安装时，输入 y 回车。选这条路线的话，以后也用这条完整的 npx 命令启动。

第四步：让页面真正能发出任务。 首次打开，按欢迎页提示登录自己的 DeepSeek 账号，或添加自己的 API Key。走 API 路线时，也可以点左下角「更多 → 设置 → 模型」，填密钥并保存；会按调用消耗 API 余额。回到新会话，在输入框右下角选模型，再按下一节添加、选中自己的工作区。全新的 Web 界面还没选工作区时，输入框不可用。[官方 Web 入门](https://deepseek-harness.github.io/deepseek-harness/guide/quickstart) · [模型配置说明](https://deepseek-harness.github.io/deepseek-harness/guide/providers)

桌面版和 Web 版选一种就够。后面装插件、开会话，都在你选的那个客户端里做。

### 03｜第一次动手：读一份原稿，把结果写回电脑

在自己的「文档」里新建一个文件夹，叫「选题练习」。用纯文本编辑器在里面存一份 素材.txt。你可以写自己的素材，也可以先写这两行：

> 本期主题：把采访录音整理成文字。

> 读者留言：一段录音里普通话和粤语混着说，转完以后怎么校对？

回到 Harness，在侧栏「工作区」旁添加文件夹，选中「选题练习」。Web 版也可以从输入框上方展开工作区菜单。然后在这个工作区新开会话，选好模型。

[/0xlangeai/article/2120769549679386878/media/2120747471966179328](/0xlangeai/article/2120769549679386878/media/2120747471966179328)

先别粘贴原文，直接发：「读一下素材.txt，告诉我读者具体卡在哪里。先别改文件。」 它能答出「两种语言混着说时怎么校对」，你就知道它读对了。接着发：

> 在同一文件夹新建「选题卡.md」，只放一个建议标题和那条读者留言的原话。不要改素材.txt。

如果弹出写入确认，核对文件名再允许。现在打开电脑上的「选题练习」：原来的 素材.txt 应该还在，旁边多了 选题卡.md。最后再让它「只把标题改成问句，留言原话不要动」，重新打开文件核对一次。

### 04｜先用别人的插件：把刚才那张卡排成一页网页

接着安装「歸藏设计」，把刚才的选题卡排成网页。

打开 Harness 侧栏的「插件」，点「添加插件」，在输入框填 dsh-guizang-design，点「安装」，完成后点「立即启用」。如果版本不兼容，先看[作者的安装说明和支持版本](https://github.com/op7418/dsh-guizang-design#%E5%AE%89%E8%A3%85)。

装好后，侧栏会出现「歸藏设计」。回到刚才的会话，在输入框敲 /，选 guizang-page-skill，再告诉它：

> 把工作区里的选题卡.md 排成一页中文网页。标题放大，读者原话单独成段，不改引语。保存为「选题卡.html」。

等它写完，在文件夹里双击 选题卡.html 看效果。刚才你安装的是一款插件，聊天框里调用的是它带来的排版技能。接下来我们照这个用法做自己的插件，只给它一条命令。

### 05｜自己做个小插件：让它知道什么样的问题值得写

我给这个插件起名 comment-pitch。希望它干的事很小：每次拿到同一格式的评论，就按同一套标准审题，不用我重新交代「别按点赞排序」「给我看原话」。

如果你已经在用自己的选题插件，可以直接去第 06 节；调用时用你自己的命令，给 Grok 的文件格式也按你的插件要求来。第一次做，就从这里开始。

打开「插件」，这次点「添加插件」右侧的小箭头，选「让 Agent 创建插件」。在打开的创造模式会话里选自己的工作区。把下面这段作为需求发给它：

[/0xlangeai/article/2120769549679386878/media/2120747486495354880](/0xlangeai/article/2120769549679386878/media/2120747486495354880)

> 帮我做一个本地选题插件，给普通会话加一条命令 /comment-pitch，并在我当前用的 Harness 里安装、启用。调用时，让当前模型读取工作区里的 comments.json。里面有一条原帖（post）、采样范围（coverage）、初筛计数（counts）和保留回复（kept）。

> 只用有原话、链接和正确父帖 ID 的直接回复作证据；重复、错串、自动回复和待复核项都不用于选题。先看原帖已经讲过什么，再找读者补出的疑问、反例或新线索。同类问题合并，最多给三个候选。每个写清：谁卡在哪里、哪句原话支撑、先做什么小实验能验证。给出「优先写／先核实／放弃」及理由。

> 把结果写成「选题判断-原帖ID.md」，存到当前工作区，保留输入文件。没有读到评论就写「材料不足」；读到了却没有值得写的问题，就如实说没有。完成后告诉我，在哪里可以调出这条命令。

接下来按创造模式里的提示确认安装和启用。等它说完成，先去「已安装插件」看开关，再回到普通会话输入 /comment-pitch。能看到、能选中这条技能，才算入口做好了。如果它只回了一段开发说明，就接着说：「请把刚做的插件实际安装到当前客户端，检查为什么普通会话里还看不到这条命令。」[官方创造模式演示](https://www.deepseek.com/harness/)

### 06｜拿一条真帖子，把流程从头跑到尾

[/0xlangeai/article/2120769549679386878/media/2120747498839113728](/0xlangeai/article/2120769549679386878/media/2120747498839113728)

中间这一步要自己动手：把 Grok 给的 comments.json 放进 Harness 工作区。

第一步：把原帖链接给自己的 Grok Bot。 挑一条和你平时创作方向有关、评论里有人讨论具体用法的 X 帖子。我这次选的是 [Avi Chawla 介绍 HarnessRouter 的原帖](https://x.com/_avichawla/status/2113954302901256597)。在自己的 [Grok Bot](https://docs.x.ai/grok-bot/overview) 对话里贴上链接，再发：

> 原帖链接：〔换成你自己的链接〕。只看这条原帖，以及最多 30 条能核对父帖的公开直接回复。剔除有明确自动化标识、或作者明确说明由 AI 自动生成的回复。纯吹捧、广告、复述也剔除，理由记为「无新信息」。有具体自动化嫌疑但证据不足的单列待复核。别凭文风、低粉或正文里 [@grok](https://x.com/grok) 判断作者身份。

> 只保留有具体疑问、可查新线索、带条件的反例或改进建议的回复。返回一个叫 comments.json 的文件：post 写原帖 id、作者 author、链接 url、原文 text；coverage 写实际读到的范围；counts 分别写 reviewed、confirmed_ai、noise、pending、kept 的条数；kept 列表逐条带 id、parent_id、author、url、text 和保留理由 reason。ID 用字符串，原话不改写。不要拿页面显示的回复总数充当已读数，不要替我起标题。

这一步别光看数字。我这次让 Grok 复核了 12 条直接回复：保留 3 条，5 条没有新信息，4 条待复核，能确认是 AI 生成的有 0 条。 一条问计费方式的回复，因为账号粉丝少、简介提到 Agent，被放进了待复核。问题明明很具体，所以我后来在指令里补上了上面那句话。这里的计数是当时的原始结果。

第二步：把 Grok 的文件交给小插件。 手动下载 Grok 发回的 comments.json。给这条帖子单独建一个文件夹，把文件放进去；回到 Harness，把这个文件夹选为工作区，新开普通会话，选好模型。输入 /comment-pitch，从候选中选中它，再发：

> 分析当前工作区的 comments.json，把值得写的问题和评论依据写进选题卡。不要改原文件。完成后告诉我文件名和首选题。

第三步：打开结果，回到原话验一次。 这次小插件用官方 deepseek-flash 实测，执行记录显示它依次加载技能、读文件、写文件，用时约 77 秒。跑的是同版本 Harness 的命令行模式。打开工作区，用这条原帖时能找到 选题判断-2113954302901256597.md；换自己的帖子，文件名末尾也会换成对应的原帖 ID。

我的卡片把[这位读者的追问](https://x.com/weichselbauml/status/2114355539811397948)排在第一。他问 “what's the advantage here?” 往后读才知道，他已经在 Grok Bot 的机器上跑 Claude Code CLI，也在浏览器里用 Claude 做研究。原帖告诉他「现在能接哪些工具」，他想知道的却是「我的办法已经能用，换了能省哪一步」。

这篇我会写成：《已经能跑 Claude Code，还要不要接 HarnessRouter？》 拿同一个小任务各做一次，对照多配了什么、省了什么，再下结论。另一条评论建议让重试事件带上审批 ID，那只说明有人想这样排障。没有查过实际记录，还不能把标题写成「这个工具的审批会丢」。

你也可以给小插件做个反向检查：另建一个工作区，放入同格式的文件，让保留列表为空、各项计数都为 0，并注明「本次未读到回复」。同一条命令应该告诉你材料不足。我实测时它确实没有硬编选题。下次换一条热帖，重复本节三步就好。
