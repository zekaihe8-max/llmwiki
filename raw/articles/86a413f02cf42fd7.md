Pi 为什么突然开始自己折腾手机端了？

两个月前我还写过一篇，分析 Pi 为什么一直不做官方桌面端和手机端

当时我觉得很合理，Pi 想守住的是极简底座，把 SDK 和 RPC 开放出去，客户端全交给社区自己折腾

但是最近翻了一圈仓库和访谈，发现风向好像真的变了

GitHub 仓库里，官方刚撤掉了旧版 Pi Mobile 的 APK 构建流程，提交备注里直接指向了新的 apps/p2

作者 Mario 最近在访谈里也提到，他自己一直在手机上高频用 PIM，而且他现在聊的下一阶段，已经不是一个人盯着一个终端，而是多台机器、多个 Agent 一起协同

Earendil 的 Armin 更是把话挑得很明，他们不想只做一家 Coding Agent 公司，而是分两条线走，一边继续守住开源底座，另一边要做连非工程师都能用明白的产品

其实这也让我想到了很多极简工具都会遇到的取舍

极简 TUI 确实是 Pi 冲到 11 万 Star 的原因，从我自己的角度来说，日常写代码、改配置也还是命令行最舒服，够轻、够干净，也不会替用户乱做决定

但是纯黑框同样也是它最大的增长天花板，GUI 和移动端才是大众更能接受的形式

以前社区虽然长出了 PI WEB、Remote Pi、ThinkRail 这些好用的客户端，但是真想把门槛降下来，让普通人在手机和电脑之间无缝切换，只靠社区松散拼接很难打通体验，官方迟早得自己立一个标准

说实话，现在也很难判断官方下场做产品后，会不会慢慢冲淡 Pi 原本那种极客味

但是对实际用它干活的人来说，核心继续保持克制，同时给非极客留一条能走通的入口，可能是现阶段更务实的选择
