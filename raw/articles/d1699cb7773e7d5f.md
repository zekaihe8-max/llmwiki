TensorTonic「从第一性原理讲清评测」：同一模型换评分和配套，排行榜结论就可能翻转

来自 [@TensorTonic](/TensorTonic) 的分享，作者先读了 Anthropic、OpenAI 和 Google DeepMind 的公开文章再写下看法，起草和核对数字时用了 AI。

评的是模型和配套一起

文中借用 Anthropic 今年 1 月的说法：完整记录是过程，结果是结束后的真实状态，两者经常对不上。订票助手可以说“已经订好了”，数据库里却没有订单；只看最后一句话，就会放过说谎的系统。评一个“智能体”，评的其实是模型加上它的配套（工具、提示词和循环），配套变好，分数同样会动。因此应当评真正要紧的结果，而不是预定路径。

CORE-Bench 上，同一套 Claude Opus 4.5 起初只有 42%；换更宽松的运行框架，并修正过严评分、含糊说明和无法复现的题目后，到了 95%。更细的过程是，换到 Claude Code 后先到约 78%，再修评分才到 95%。框架变化本身就占了很大一块。

多跑几次，还要看误差和规则

模型输出不稳定，只跑一次意义不大。pass@k 是 k 次里至少成功一次的概率，适合可以多试几次再留下能过测试的补丁；pass^k 是 k 次全成功的概率，更适合直接面向用户的场景。单次成功率 75%、跑 3 次时，前者大约 98%，后者大约 42%。排行榜还常省略误差：500 道题、得分 80%，95% 区间大约在 76.5% 到 83.5%；另一模型得 82%，单看这两个数字还分不出谁更好。

OpenAI 写过，多数基准只分对错，猜永远比说“我不知道”更划算。GPT-5 系统卡在 SimpleQA 上的数字是：旧的 o4-mini 只在 1% 的题上弃答，答对 24%，答错 75%；gpt-5-thinking-mini 弃答 52%，答对 22%，答错只有 26%。只看准确率，旧模型还略高一点，错得却大约是后者的三倍。分数只告诉你失败有多频繁，只有完整记录能分清，是模型错了，还是评分器把合理答案判错了。
