OpenAI 给 GPT-6.2 的 Codex 提示建议：先说验收标准，再按任务选推理强度

OpenAI 在这份指南里写，GPT-6.2 Astra 比 GPT-6 Astra 更容易给出接近可用的初稿：代码更好读，写作更直接，视觉作品也更完整。这些提示方法适用于整个 GPT-6.2 系列，包括 Astra 和 Sol，重点是在 Codex 里把任务说清楚，并告诉它你会按什么标准验收。

指南建议，像跟熟悉项目的同事交代工作一样描述需求，同时写明验收时会看什么。比如图标必须在 24 像素工具栏里仍能辨认，就直接说出来。Codex 可以从现有图标里抓住风格，并判断在这个尺寸下该保留多少细节。

按调查深度选择推理强度

更高的推理强度，能让模型在长时间任务里坚持做到最后的检查，即使最终答案只有几行。关键是先说清什么叫完成，以及哪些地方必须穷尽。如果团队要的是一项建议，可能意味着要把一条有希望的线索推到足够远，再拿去对照其他解释。

选择推理强度，看的是调查有多深：快速浏览可以用 Medium；追查一个可能的原因、并跨越多个系统时，适合用 High；当多个原因可能相互影响、调查需要逐一交代时，再考虑 Extra High。

让并行工作变成可授权的默认选择

当任务可以拆成几块独立推进时，明确告诉 Codex 按需使用子 agent，等于授权它自己判断何时并行、如何分工。如果这类工作经常出现，就把这条写进对应的 skill 或 AGENTS.md，并说明适用场景。比如研究类技能，可以规定：请求里包含多个独立问题时再启用。

使用 Ultra 时，Codex 会自己决定要不要引入子 agent。指南建议把它留给能干净拆开、又足够深入的任务，例如开放式研究里每一问都值得单独深挖。每个子 agent 可以带着自己的工作上下文，顺着一条线索往下做。

先给视觉参考，再按真实尺寸验收

如果心里已有特定视觉效果，先给一张参考图，说明形状怎么组合、哪些颜色更突出、视线应先落在哪里。可以从设计软件里导出，也可以让 Codex 用 GPT Image 先生成一张。参考图对了之后，再让它制作素材、渲染，并对照参考图反复修改。

验收时要按人们实际看到的尺寸来看，大图上清楚的细节，到成品里可能消失。如果结果是可交互的，还要让它亲自试一遍应当支持的操作。SVG 与 3D Design 插件里有一份技能，会引导 Codex 按这个流程处理可编辑插图和三维模型。

让 AGENTS.md 保持精简

AGENTS.md 用来写项目要求和约定，尤其是 Codex 无法从代码、测试或文档里推断出来的部分。项目依赖某套工作流时再写进去，日常怎么执行的细节交给 Codex。

Codex Cloud 里每个任务都有独立虚拟机。如果一边让它工作、一边还要用自己的电脑，可以在个人的 ~/.codex/AGENTS.md 里引导它优先使用不会抢占当前应用的工具。比如查一封邮件时，鼓励它走已有的邮件连接，而不是打断正在使用的软件。多 agent 共用同一台机器时，让它们控制同时跑多少构建和测试，尽量给其他任务留出资源；真正吃重的任务再独占整机。收尾时，让每个 agent 停掉自己启动的后台任务，并清理不再需要的临时文件。
