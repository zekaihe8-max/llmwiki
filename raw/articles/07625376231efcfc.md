Philipp Schmid 为什么会在 2027 更看好 MCP ？
-- Skills 和命令行兴起后 MCP 挨过骂，但 Code Mode、内置 Skills 和事件推送正在把它拉回来！

Google DeepMind 负责 Agents 与 Gemini API 的 Philipp Schmid 写了一篇「Why I'm Bullish on MCP for 2027」。回顾过去大约 18 个月：MCP 先被热捧，很快又因上下文膨胀遭到反弹；Skills 出现后，不少开发者转向命令行和按需披露。他一直不认同这种转向，并认为风向正在回来。

在 Linear 和 Notion，Agent 已创建大约一半的 issue 和页面，其中 issue 约每周 240 万条，Notion 还称 MCP 流量增长了 60 倍；Atlassian 每个工作日有超过 500 万次 MCP 工具调用，其中 44% 的使用者不在软件团队，命令行本来就不是选项；Neon 上经 MCP 的智能体用量每周增长 14%；苹果也已为 Pages、Numbers 和 Keynote 提供本地 MCP 服务器。后来的规范去掉了有状态会话，并加入官方扩展。Philipp 表示，进入 2027 年，自己对 MCP 更有信心。

# Code Mode 加上类型声明，中间结果不必再堆进上下文

真正的任务很少只调一次工具。按普通工具调用，每一步都要再走一轮模型，还要把中间结果倒进上下文；若要跨两个 MCP 服务器拼接数据，模型的上下文就成了临时内存。Code Mode 的做法是：Harness 给模型一个沙箱，把 MCP 工具暴露成可调用的函数。他认为这已在 OpenCode 2.0、Claude Code、OpenAI Codex、Pi 和 Factory Droid 里逐渐成为默认。

前提是服务器同时给出 inputSchema 和 outputSchema，客户端才能先生成带类型的接口，并把 structuredContent 直接传回。模型于是可以在一份脚本里连续调用、在内存里过滤和拼接，只把真正有用的摘要送回上下文。和命令行相比，MCP 本来就能同时返回结构化数据和图片、音频等块。鉴权也更干净：客户端在沙箱外处理按用户的 OAuth 2.1 和权限范围，不必把宽权限密钥写进磁盘或环境变量再交给智能体。

# Skills 被收进 MCP 之后，更新可以跟着摘要走

「Skills 加命令行」和 MCP 的争论，也可能因此收场。过去团队往往一边做命令行或 MCP 服务器，一边再维护一份单独的 SKILL.md。现在的 Skills 扩展把 Skills 放进 MCP：每个 Skill 有 skill:// 地址、解析过的 YAML 头信息，以及带 SHA-256 摘要的文件清单。厂商在服务器上更新 Skills 后，摘要会变，客户端就能自动拉取，不必再靠人工同步。Anthropic 已在 Claude 和 Claude Code 里以公开测试的形式提供「Skills over MCP」，Shopify、HubSpot、Atlassian 这类服务器可以按登录账号或组织下发对应的操作说明。

占用上下文的方式仍然很轻：连接时只把名称和简介写入系统说明；真正用到时，再读取完整 SKILL.md，或按摘要缓存到本地再让 Agent 去读。

# 事件扩展让 Agent 在人离开时也能被叫醒

下一步是多人协作和始终在线。此前 MCP 基本是主动拉取，外部系统很难把智能体叫醒。现在处于测试阶段的 Events 扩展提供三种送达方式：Webhook 适合 ChatGPT 这类可暴露回调地址、人已离开的远程环境；推送适合 OpenCode 2.4.0 这类本地进程，用来接构建或部署日志；轮询则给没有公网地址的本地命令行或无服务器部署。客户端会跟踪游标、按 eventId 去重，再把事件交给 Harness。他举的例子是凌晨两点的 P0 安全告警：智能体被叫醒后先拉日志、整理分诊，不必等有人打开收件箱。Shop MCP 的订单更新、Vercel 的部署成功，已经开始提供事件。再配合 MCP Tasks，异步流程就不必再单独搭一套 webhook。

# 界面可以嵌进客户端，最好的 Harness 也会把自己做成 MCP 服务器

若只返回 JSON 和纯文本，看延迟图、筛选看板或翻设计稿仍然别扭。MCP Apps 允许服务器在兼容的客户端里直接给出沙箱化的交互页面。Slack 的新 MCP 客户端、Claude 的交互式连接器，以及 Google Antigravity，已经能在对话、侧栏或文件预览里渲染这类界面。

他也指出仍有缺口：服务器往往只看见工具调用，看不见用户在谈什么；发现机制还要向多家注册中心重复提交；不受信任的 webhook、Code Mode 沙箱和嵌入式页面，都会扩大提示注入面。

他更向前的判断是：2027 年最好的 Agent Harness，会赢在 MCP 集成上，而且 Harness 自己也应当是一个 MCP 服务器。子 agent 可以做成 MCP Tasks，共用一块「群体看板」来发布发现、认领工作，任务结束再用事件叫醒协调者。好的 MCP 服务器应当给 Agent 提供工具，而不是把整个产品收成一个 ask_agent 端口；那种做法会让对方拿不到你这边已经有的上下文。普通服务器应把类型清楚的工具和数据做好，把「智能体作为 MCP 服务器」留给跨子智能体、团队或公司的长程协作。
