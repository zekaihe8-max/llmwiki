# Gemini API CLI (gemini-api)

[#gemini-api-cli-gemini-api](#gemini-api-cli-gemini-api)

[https://github.com/google-gemini/gemini-api-cli/releases](https://github.com/google-gemini/gemini-api-cli/releases)
[https://opensource.org/licenses/Apache-2.0](https://opensource.org/licenses/Apache-2.0)

Gemini models and managed agents for the agent you already use.

Give Codex, Claude Code, Antigravity, OpenClaw, Hermes, or any other agent with shell access the ability to use the Gemini API. Configure an API key, put gemini-api on PATH, and let your agent choose a model, generate an asset, analyze a file, or launch a managed agent to handle a task.

Your agent plans the work. Gemini provides models and managed agents. This stateless CLI connects them through standard shell commands:

```
gemini-api image <span class="pl-s"><span class="pl-pds">"</span>A friendly robot mascot for a developer tool<span class="pl-pds">"</span></span> --out ./assets/
```

A prompt goes in. An image lands in your project. Your agent gets the file path and keeps building. The same binary can return an analysis, a voiceover, a transcript, or the interaction ID of a background managed-agent run.

## Why this CLI

[#why-this-cli](#why-this-cli)

A coding agent building an app may need a hero image, a voiceover, a second opinion on a design, or an answer inside a PDF. An assistant may need to turn a recording into captions or delegate multi-step research. Give that agent gemini-api and an API key, and it can call those capabilities directly when the task requires them.

- One binary for models, media, and managed agents: Access text and reasoning models, multimodal file analysis, image/audio/music/video generation, and managed agents from the command line.

- Delegate long-running work: Start a Gemini managed agent in the background, keep the returned interaction ID, and retrieve the result when needed.

- Self-describing interface: Commands, flags, request schemas (--schema), and machine-readable usage (--usage) are built into the binary so an agent can inspect what it needs on the fly.

- Safe dry-run validation: --dry-run validates inputs and prints the resolved HTTP request with credentials redacted—without making a network call or reading the OS keychain.

- Script- and agent-friendly output: Stream text, write media directly to disk, emit structured JSON (--output-format json) or compact TOON (--output-format toon), or filter fields inline with --jq.

- Stateless execution: Each invocation runs independently. Your agent supplies the context, chooses the model, and controls the next step.

Built for headless use by coding agents and assistant tools, with the same interface available to shell scripts and CI jobs. A single Go binary runs on macOS, Linux, and Windows.

go install github.com/google-gemini/gemini-api-cli/cmd/gemini-api@latest

## Quick start

[#quick-start](#quick-start)

### 1. Configure your API key

[#1-configure-your-api-key](#1-configure-your-api-key)

Create an API key in Google AI Studio (see the [Gemini API key docs](https://aistudio.google.com/docs/api-key)) and make it available to your shell or your agent's subprocess environment:

```
<span class="pl-k">export</span> GEMINI_API_KEY=<span class="pl-s"><span class="pl-pds">"</span>YOUR_API_KEY<span class="pl-pds">"</span></span>
```

>

Workstation tip: To persist your key in your OS keychain (macOS Keychain, Linux Secret Service, or Windows Credential Manager) or ~/.config/gemini-api/config.yaml, run gemini-api configure --api-key "YOUR_API_KEY" or open the interactive form with gemini-api configure --interactive. Check your active configuration and credential source at any time with gemini-api whoami.

Verify your setup locally with --dry-run (no network call), then remove --dry-run to call the API:

```
gemini-api generate <span class="pl-s"><span class="pl-pds">"</span>Hello from my agent<span class="pl-pds">"</span></span> --dry-run
gemini-api generate <span class="pl-s"><span class="pl-pds">"</span>Hello from my agent<span class="pl-pds">"</span></span>
```

### 2. Give your agent instructions

[#2-give-your-agent-instructions](#2-give-your-agent-instructions)

Add the following block to your agent's instructions (AGENTS.md, CLAUDE.md, .cursorrules, or tool configuration):

```
You have access to gemini-api through the shell.
Use it to call Gemini models, generate or edit media, analyze files, or launch managed agents.
1. Inspect --help or --usage to choose a command, and --schema when building a --body JSON payload.
2. Preview API calls with --dry-run (or --dry-run --output-format json).
3. For discrete JSON output or --jq filtering on streaming commands (generate, agent run, agent status --stream), pass --stream=false --output-format json (--background on agent run returns a single interaction without streaming unless --stream is passed).
4. Capture returned file paths (from media commands) and interaction IDs (from agent/model runs) to continue multi-step tasks.
```

### 3. Put your agent to work

[#3-put-your-agent-to-work](#3-put-your-agent-to-work)

Prompt your host agent as usual:

```
Build a landing page for this app. Use Gemini to create a mascot image and a welcome voiceover, and launch a managed research agent to investigate competing products. Incorporate the assets and findings into the page.
```

Your agent chooses the commands, runs them in its shell, and uses the returned file paths and interaction IDs in its own workflow.

## Agent discovery and machine interface

[#agent-discovery-and-machine-interface](#agent-discovery-and-machine-interface)

Everything an agent needs to use gemini-api is discoverable from the binary itself, without external documentation or credentials:

When an agent needs to…
It runs…

Discover commands and flags

gemini-api --help or gemini-api --usage

Inspect a request body schema

gemini-api agent run --schema

Validate and preview a call offline

gemini-api image "A robot mascot" --dry-run

Parse a complete structured response

gemini-api generate "Hello" --stream=false --output-format json

Extract a single field inline

gemini-api agent list --jq '.agents[].id'

- --usage outputs the complete command tree, flags, defaults, environment variables, and config keys as machine-readable [KDL](https://kdl.dev).

- --schema prints the bundled JSON Schema (draft 2020-12) for any command that accepts a request body.

- --dry-run validates flags and payloads and previews the HTTP request without credentials or network access (use --dry-run --output-format json for machine-parseable JSON request previews).

- --no-interactive disables all interactive prompts and TUI forms.

- --agent-mode (or GEMINI_CLI_AGENT_MODE=1) enables structured JSON error envelopes on stderr and defaults stdout to compact [TOON](https://github.com/toon-format/spec) output (--output-format json explicitly selects JSON).

- Exit codes distinguish success (0), runtime/API failures (1), invalid usage/validation errors (2), and authentication/authorization failures (3).

Run gemini-api --help-global to see all global authentication, network, output, and diagnostic flags.

## Agent workflows

[#agent-workflows](#agent-workflows)

### 1. Generate and edit creative assets

[#1-generate-and-edit-creative-assets](#1-generate-and-edit-creative-assets)

Coding agents like Codex, Claude Code, or Antigravity can generate images, speech, music, and video while building an app:

```
<span class="pl-c"><span class="pl-c">#</span> Generate an image and capture the written file path</span>
MASCOT_PATH=<span class="pl-s"><span class="pl-pds">$(</span>gemini-api image <span class="pl-s"><span class="pl-pds">"</span>A friendly robot mascot, soft studio lighting<span class="pl-pds">"</span></span> --out ./assets/mascot.jpg<span class="pl-pds">)</span></span>

<span class="pl-c"><span class="pl-c">#</span> Edit an existing image with -i / --input</span>
gemini-api image <span class="pl-s"><span class="pl-pds">"</span>Add a winter scarf and snowy background<span class="pl-pds">"</span></span> -i <span class="pl-s"><span class="pl-pds">"</span><span class="pl-smi">$MASCOT_PATH</span><span class="pl-pds">"</span></span> --out ./assets/mascot-winter.jpg

<span class="pl-c"><span class="pl-c">#</span> Generate single-speaker or multi-speaker voiceovers</span>
gemini-api tts <span class="pl-s"><span class="pl-pds">"</span>Welcome. Let's build something together.<span class="pl-pds">"</span></span> --out ./assets/welcome.wav
gemini-api tts <span class="pl-s"><span class="pl-pds">"</span>Alice: Welcome to the demo! Bob: Let's dive right in.<span class="pl-pds">"</span></span> \
  --multi-speaker <span class="pl-s"><span class="pl-pds">"</span>Alice=Kore,Bob=Puck<span class="pl-pds">"</span></span> \
  --out ./assets/dialogue.wav

<span class="pl-c"><span class="pl-c">#</span> Generate background music and video</span>
gemini-api music <span class="pl-s"><span class="pl-pds">"</span>Warm ambient music for a product walkthrough<span class="pl-pds">"</span></span> --out ./assets/
gemini-api video <span class="pl-s"><span class="pl-pds">"</span>A slow camera move through a sunlit workshop<span class="pl-pds">"</span></span> --out ./assets/
```

Media commands write files locally and print only the written file path to stdout. When --out points to a directory (or is omitted), the CLI names the file automatically using the file extension that matches the API's returned MIME type (for example, .jpg for image/jpeg, .wav for audio/wav, .mp3 for audio/mpeg, and .mp4 for video/mp4).

### 2. Analyze documents and transcribe recordings

[#2-analyze-documents-and-transcribe-recordings](#2-analyze-documents-and-transcribe-recordings)

Assistants like OpenClaw or Hermes can turn documents, media files, and YouTube URLs into answers and deliverables:

```
<span class="pl-c"><span class="pl-c">#</span> Analyze a PDF or compare multiple images</span>
gemini-api analyze --input product-brief.pdf <span class="pl-s"><span class="pl-pds">"</span>What should we build first, and why?<span class="pl-pds">"</span></span> <span class="pl-k">></span> plan.md
gemini-api analyze --input before.png --input after.png <span class="pl-s"><span class="pl-pds">"</span>Summarize the visual design changes<span class="pl-pds">"</span></span>

<span class="pl-c"><span class="pl-c">#</span> Transcribe audio or video (valid formats: md, text, json, srt)</span>
gemini-api transcribe --input interview.mp4 --format srt --out interview.srt
```

For larger media files (over ~14 MB raw / 20 MB base64-encoded), upload once with files upload --wait and reuse the returned files/<id> URI across analyze, transcribe, generate, image, video, or agent run:

```
FILE_URI=<span class="pl-s"><span class="pl-pds">$(</span>gemini-api files upload interview.mp4 --wait --output-format json --jq <span class="pl-s"><span class="pl-pds">'</span>.name<span class="pl-pds">'</span></span><span class="pl-pds">)</span></span>
gemini-api analyze --input <span class="pl-s"><span class="pl-pds">"</span><span class="pl-smi">$FILE_URI</span><span class="pl-pds">"</span></span> <span class="pl-s"><span class="pl-pds">"</span>List the key action items with timestamps<span class="pl-pds">"</span></span>
```

### 3. Launch and poll a background managed agent

[#3-launch-and-poll-a-background-managed-agent](#3-launch-and-poll-a-background-managed-agent)

Delegate multi-step research or coding tasks to a Gemini managed agent such as Deep Research. Pass --background so the CLI returns a single interaction (no stream, unless --stream is passed) with the interaction ID immediately instead of holding open an SSE stream:

```
INTERACTION_ID=<span class="pl-s"><span class="pl-pds">$(</span>gemini-api agent run <span class="pl-s"><span class="pl-pds">"</span>Research battery recycling approaches and cite sources<span class="pl-pds">"</span></span> \</span>
<span class="pl-s">  --agent deep-research-preview-04-2026 \</span>
<span class="pl-s">  --background \</span>
<span class="pl-s">  --jq <span class="pl-s"><span class="pl-pds">'</span>.id<span class="pl-pds">'</span></span><span class="pl-pds">)</span></span>
<span class="pl-c1">echo</span> <span class="pl-s"><span class="pl-pds">"</span>Started interaction: <span class="pl-smi">$INTERACTION_ID</span><span class="pl-pds">"</span></span>
```

Check progress or retrieve the finished output using the returned INTERACTION_ID:

```
gemini-api agent status <span class="pl-s"><span class="pl-pds">"</span><span class="pl-smi">$INTERACTION_ID</span><span class="pl-pds">"</span></span> --stream=false --output-format json
```

You can also stream live progress events (gemini-api agent status "$INTERACTION_ID" --stream) or cancel an active run (gemini-api agent cancel "$INTERACTION_ID").

### 4. Choose the right model

[#4-choose-the-right-model](#4-choose-the-right-model)

Use --model (-m) on generation and analysis commands to pick a model for reasoning, fast text, multimodal understanding, or media generation:

```
<span class="pl-c"><span class="pl-c">#</span> View the curated offline model catalog grouped by capability</span>
gemini-api models

<span class="pl-c"><span class="pl-c">#</span> Query all live models available to your API key (--all auto-paginates across pages)</span>
gemini-api models list --all
gemini-api models get gemini-4-hydrogen

<span class="pl-c"><span class="pl-c">#</span> Run a prompt with a specific model</span>
gemini-api generate <span class="pl-s"><span class="pl-pds">"</span>Review this approach: cache immutable responses by content hash<span class="pl-pds">"</span></span> --model gemini-4-hydrogen
```

## Go deeper: custom request bodies (--schema to --body)

[#go-deeper-custom-request-bodies---schema-to---body](#go-deeper-custom-request-bodies---schema-to---body)

Short flags cover common tasks; --body gives your agent full access to the underlying Interactions API request schema while keeping the CLI's file output and error handling.

First, inspect the schema for image:

```
gemini-api image --schema <span class="pl-k">></span> image-schema.json
```

Next, create hero-image.json to select gemini-nano-banana-2.1, request a 16:9 image at 2K size (image_size: "512", "1K", "2K", or "4K"), and disable server-side interaction storage ("store": false):

```
cat <span class="pl-k">></span> hero-image.json <span class="pl-s"><span class="pl-k"><<</span>'<span class="pl-k">JSON</span>'</span>
<span class="pl-s">{</span>
<span class="pl-s">  "model": "gemini-nano-banana-2.1",</span>
<span class="pl-s">  "input": "A friendly robot mascot in a sunlit workshop, composed on the right with uncluttered space on the left for a landing page headline. No text or watermark.",</span>
<span class="pl-s">  "response_format": {</span>
<span class="pl-s">    "type": "image",</span>
<span class="pl-s">    "aspect_ratio": "16:9",</span>
<span class="pl-s">    "image_size": "2K"</span>
<span class="pl-s">  },</span>
<span class="pl-s">  "store": false,</span>
<span class="pl-s">  "stream": false</span>
<span class="pl-s">}</span>
<span class="pl-s"><span class="pl-k">JSON</span></span>
```

Preview the exact HTTP payload with --dry-run, then execute the request:

```
gemini-api image --body @hero-image.json --out ./assets/hero.jpg --dry-run --output-format json
gemini-api image --body @hero-image.json --out ./assets/hero.jpg --output-format json
```

With --output-format json, the CLI writes the image to disk and returns structured artifact metadata on stdout:

```
{
  <span class="pl-ent">"kind"</span>: <span class="pl-s"><span class="pl-pds">"</span>image<span class="pl-pds">"</span></span>,
  <span class="pl-ent">"mime_type"</span>: <span class="pl-s"><span class="pl-pds">"</span>image/jpeg<span class="pl-pds">"</span></span>,
  <span class="pl-ent">"path"</span>: <span class="pl-s"><span class="pl-pds">"</span>/path/to/project/assets/hero.jpg<span class="pl-pds">"</span></span>,
  <span class="pl-ent">"size_bytes"</span>: <span class="pl-c1">2914159</span>,
  <span class="pl-ent">"status"</span>: <span class="pl-s"><span class="pl-pds">"</span>completed<span class="pl-pds">"</span></span>
}
```

--out controls the local file destination; response_format controls what the model generates (pass --raw-response instead of --out if you want the full raw API response envelope). The same --schema to --body workflow applies to gemini-api agent run and other commands when configuring system_instruction, tools, structured JSON response_format.schema, or stateful multi-turn continuations via previous_interaction_id:

```
<span class="pl-c"><span class="pl-c">#</span> Turn 1: Run a non-streaming interaction and capture its ID</span>
TURN1_ID=<span class="pl-s"><span class="pl-pds">$(</span>gemini-api generate <span class="pl-s"><span class="pl-pds">"</span>Propose 3 database indexing strategies for a time-series log table.<span class="pl-pds">"</span></span> \</span>
<span class="pl-s">  --stream=false --jq <span class="pl-s"><span class="pl-pds">'</span>.id<span class="pl-pds">'</span></span><span class="pl-pds">)</span></span>

<span class="pl-c"><span class="pl-c">#</span> Turn 2: Continue the conversation using previous_interaction_id</span>
gemini-api agent run <span class="pl-s"><span class="pl-pds">"</span>Compare strategy #2 and #3 for write-heavy workloads.<span class="pl-pds">"</span></span> \
  --body <span class="pl-s"><span class="pl-pds">"</span>{<span class="pl-cce">\"</span>previous_interaction_id<span class="pl-cce">\"</span>: <span class="pl-cce">\"</span><span class="pl-smi">$TURN1_ID</span><span class="pl-cce">\"</span>}<span class="pl-pds">"</span></span> \
  --stream=false
```

The CLI stores no local conversation state—server-side interactions and uploaded files manage their own retention on the API, and your workflow keeps only the IDs it wants to reuse.
