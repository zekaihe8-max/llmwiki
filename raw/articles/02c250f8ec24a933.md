DeepSeek 这次开源的 Super-agent，有一种 PI Durable 的味道了🔥

最近 DeepSeek Harness 团队放出了一套 Super-agent 架构设计，还开源了对应的研究原型

我看了一下整个设计，发现它想解决的不是 Agent 能不能完成某个任务，而是怎么让 Agent 长期运行、主动接活、持续跟进，还尽量减少人工干预

整理了我觉得对实际工程最有价值的 5 个地方：

1、任务不再依赖单个 Session

以前很多 Agent 都是一次对话对应一次任务，任务结束或者会话中断，后续还得自己重新安排

Super-agent 引入了 Ticket 机制，每个任务都有自己的状态、授权范围和执行记录

比如 Agent 提交了一个 PR，后面有人提出修改意见，它还能根据原来的任务继续处理，不需要重新解释一遍背景

2、Router 和 Worker 分离

Router 负责接收消息、判断任务和分配工作，真正执行的是独立的 Worker

每个任务都有自己的 Session 和工作目录，还能并行处理

我觉得这个设计比较合理，主 Agent 不需要把所有代码和执行过程都塞进自己的上下文，也能避免多个任务直接混在同一个工作目录里

3、从被动聊天变成事件驱动

目前原型支持监听 GitHub 和飞书的消息

比如 GitHub 出现新的 Issue、PR 评论或者 CI 结果，都可以成为触发事件

但它不是看到消息就直接执行，而是先根据授权和规则判断，符合条件才会创建任务

甚至可以先开观察模式，只记录它准备做什么，不真正执行

4、任务中断后可以恢复

这也是长期运行的 Agent 最需要解决的问题之一

Worker 执行到一半，遇到网络错误、模型请求失败或者服务重启，系统会保留任务状态，并通过重试和恢复机制继续处理

不会简单地把一次模型调用失败当成整个任务结束

5、尽量减少对人的打扰

这个反而是我最喜欢的设计理念

作者强调的不是让 Agent 做更多事情，而是让它消耗尽可能少的人类注意力，提供尽可能多的价值

任务执行过程中不需要每一步都汇报，只有需要人工决定、遇到问题或者有结果交付时才通知你

就是让我感觉 好像所有开源比较出名的 Agent 都在往持久化运行 低打扰方面优化，和我前面研究的 pi Durable 有异曲同工之妙

都是往自恢复和Agent持久化方面走，可能最终的大方向都是 person agent
