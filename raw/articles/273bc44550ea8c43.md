# 主动性体现在行动前的判断

主动式 Agent 带着长期目标观察环境，自行决定是否行动、何时行动，以及介入多深。每天定时执行同一项任务，只能说明实现了自动化，还不一定具有这种判断能力。

原文用 worth_acting_on() 表示这一步。例如，航班延误两小时，Agent 需要判断：会不会影响后续行程？现在提醒，还是稍后再检查？只提供建议、请求批准，还是直接改签？

这些选择都依赖记忆。同一条延误消息，对不同旅客可能意味着完全不同的处理方式。选择“等待”，还意味着安排下一次检查。

# 沉默也要记录，才能发现遗漏

聊天助手的回答通常有人阅读，主动式 Agent 的大量运行却可能停在后台，最终什么都不做。没有判断记录，就很难发现它错过了多少重要事件。

建议记录每次触发、参考信息、选择、行动程度及理由。若系统先做轻量过滤，再交给模型深入判断，两层都应留下记录。“保持沉默”可以是正确结果，但必须能够事后检查。

评测时，需要分开看三类错误：行动太频繁，造成打扰；过于保守，漏掉应处理的事；介入过深，本该先问却直接执行。作者自己的助手就曾对已经取走的包裹连续提醒五次。

# 用情境评测，按风险设置门槛

评测样本应从“问题与标准答案”，扩展成“情境与应有判断”，包含触发事件和当时的记忆快照。

精确率看采取的行动中，有多少确实值得做；召回率看所有该做的事情中，抓住了多少。除此之外，还要检查动作是否越界。轻提醒和花钱下单的代价不同，不能共用一道行动门槛。

修改提示、模型、记忆或判断门槛后，都应重新评测，并区分问题出在判断，还是出在记忆缺失、过期。
