每天三万次合并：Anthropic 靠「可验证证据」而不是更多人工读 diff

来自 [@kapmani](/kapmani) 和 [@addyosmani](/addyosmani) 在 [@aiDotEngineer](/aiDotEngineer) 的分享，当 Coding agent 让「写代码」不再是瓶颈；真正卡住的是有没有足够证据敢合并。Addy 称 Anthropic 日合并量大约从五月的 2500 提到约 30000：Claude 做首轮审查，但必须附带端到端、浏览器、lint、测试、截图/视频等证据；人审的是证据包，不是逐行啃完所有 diff。Manish 的收尾总结：写得快不等于发得快；自主权是挣来的。
[youtube.com/watch?v=AnsXWH…](https://t.co/R62YHtJYDy)

现场讲了什么？
举手调查：几乎人人让 agent 开过 PR，真正「每行都人工看完再合」的很少。CircleCI 侧写：CI 吞吐大涨，约三成合并尝试仍失败。框架是 software factory / 软件产线：亮灯工厂里人仍在规划–构建–检查–发布里用判断和品味；黑灯工厂更接近产线全自动，人主要定意图、处理大例外。多数团队处在光谱中间。

Anthropic 怎么扛住这么大规模 PR ？
流程：Claude 首轮审查 → 尽量像真用户一样试产品（浏览器、工具、lint、各类检查）→ 发现缺口用 hooks 盯编辑与 diff、尽快修 PR → 把团队约定写进 CLAUDE.md / agents.md 之类 → 人核对 agent 交出来的证据（含 UI 录屏、截图）。Addy 强调：只说「verify」太空；要落到端到端、property、视觉验证等具体测法，才谈得上自动合并。Claude Opus 5.5 模型已经够用，下一波收益更在验证实践与分享。

[@SonarSource](/SonarSource) 侧：多层验证与护栏
State of Code 方向：多数人觉得 AI 让功能更快上线，PR 更大更复杂，仍有相当比例代码未经充分审查进生产；对受监管场景尤其刺眼。建议零信任、每个环（agent 环、CI 环、维护环）都有独立验证：确定性层抓注入/溢出等；agent 审查抓逻辑与意图；供应链层看 CVE、恶意包。企业还要管 agent 身份、遥测、权限与沙箱；他们更爱说 guide rails（导轨）：把 agent 限制在批准路径上，而不是事后拦。

快问快答要点
2027 年底多数团队：偏「亮灯 + 若干暗角」，不太可能全体暗灯。Agent 写的 PR 建议打标（短期审计、额外检查清单）；责任仍在发起人：你 kick 了 Claude 跑完，出事还是你修。初级/负责人今年该练：弄清「验证」在自家产品里到底指什么测试。何时可合：你有充分信心，或已把风险压到可接受。
