多Agent 到底怎么使用才是对的？

当下很多时候都在推崇多 Agent 去干活，但是实际完成的效果会很一般，甚至是不堪入目

以前我不知道怎么去形容，只能说自己遇到的真实情况，直到看到了 Devin 团队（Cognition）写的《Don't Build Multi-Agents》这篇文章

里面列出来的三个核心观点，直接把问题讲透了：

1. 共享上下文必须共享完整的执行轨迹，而不只是几句消息

真实任务里往往藏着多轮对话和工具调用的细节，只把拆好的子任务扔给子 Agent，信息残缺必然导致各自理解跑偏，最后拼出来的东西根本没法看

2. 每个动作都隐含着决策，并行干活极易互相打架

文章举了个很形象的例子：做一个 Flappy Bird，拆成一个子 Agent 做背景、一个做小鸟，哪怕前面信息都同步了，但是并行时互相看不见对方在干嘛，最后拼一起画风和逻辑全是冲突

3. 宁可用单线程保持上下文连续，也别硬上多 Agent

与其引入失控的决策冲突，不如用单线程线性把事做完，上下文撑爆了再专门做历史压缩；

连 Claude Code 的子 Agent 用法都很克制，只用来查资料回答问题，绝不并行写代码

我也很认同文章里面的内容，因为很多时候我要不就是开一个新的 Agent 去单独处理任务，要不就是只用一个 Agent 从 0-1 的完整执行

如果遇到上下文不够的情况，要不就是保留任务节点，开一个新的去执行，要不就是压缩上下文继续任务

我觉得现阶段 Agent 还没有找到比较好的多 Agent 处理的方案，希望这篇文章对你也有启发
