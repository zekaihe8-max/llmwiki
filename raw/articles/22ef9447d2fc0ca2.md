# Grok Bot 从 0 到 1，装好之后怎么用，看这篇就够了

22 min read
[/xiaomovps/article/2115738442181333337/media/2115737473234223104](/xiaomovps/article/2115738442181333337/media/2115737473234223104)

9 月 10 日写的那篇 Grok Bot 教程，现在有将近半篇可以直接跳过了。

当时为了接上 X，我用了很大篇幅教大家申请开发者账号、创建项目和 App，现在这些步骤都不需要了。

这一个多月，我又陆续在 X 上发了 49 条 Grok Bot 的帖子。写这篇之前，我把以前的内容重新核对了一遍，发现有 5 处重要变化：连接 X 的方式变了，读数据、写草稿和看私信不再消耗 X 的额度，X 连接器能做的事情更多了，$30 一档的会员也能用 Grok Bot，手机 APP 也打通了。

还有一些限时福利，比如 10 月 11 日 MLH 送 Cursor Pro，早就已经过期。照着旧帖子一步步操作，很容易白忙一场。

但门槛变低了，不代表装好以后就知道怎么用。

第一天只会让它查天气、看新闻，跟普通 Grok 没什么区别。过几天想让它真正干活，又开始自己堆提示词，写得越来越长。用上一阵子，旧记忆和旧规则还可能反过来影响它做事。

所以这次我不打算再堆一份功能清单，而是用一个帮我运营 X 的 Bot 做例子，从开通、连接 X、套用现成模板，到最后清理记忆，完整走一遍。

先说结论：刚开始用 Grok Bot，做好三件事就够了。

- 第一天：先接上 X，让它用一条只读指令找出你最新的三条帖子，再自己去 X 核对结果；
- 第一周：别急着从零写提示词，先从模板市场挑一个现成的 Bot，让它帮你完成一件真实任务；
- 之后每半个月：给它做一次记忆大扫除，把过时的规则和不再需要的内容清理掉。

备份、额度和写代码这些进阶内容，我也放进去了，按自己的需求看就行。

> 先说时间：本文的功能、额度和限制，是 2026 年 10 月 29 日对照官方页面和我自己的使用情况整理的。Grok Bot 更新很快，实际操作时仍以官方页面为准。

## 一、开始之前：五分钟搞懂 Grok Bot

### 1. 不是问它问题，是交给它一件事

普通 Grok 偏对话、搜索和生成，回答完这件事就结束了。

Grok Bot 配了一台持续运行的云电脑。你交给它一项工作，它会继续打开浏览器、用终端、调用插件，把实际结果带回来。你关掉对话，任务也可以接着跑。

所以用 Grok Bot 的思路要换一下：不是问它问题，而是交给它一件事。

### 2. 为什么是它

主流的几个 Personal Agent 我都用过：Meta 的 Muse、Grok Bot、OpenAI 的 Dots、Manus 的 Cue。我自己的分档是这样的：

梯队

产品

我的感受

第一梯队

Muse

最接近我想要的 Personal Agent，能打电话、发邮件、操作浏览器、生成图片视频，短板是编程

第二梯队

Grok Bot

几乎没有明显短板。X 相关的事情有加成，编程靠 Cursor 补，浏览器操作不如 Muse 丝滑

第三梯队

Dots、Cue

更像半成品

那为什么我主力用的还是 Grok Bot？对我来说，最重要的是两点：一是能丝滑地搜索 X 上的内容，运营和分析账号离不开它；二是手机上就能把九成的工作交代下去，不用开电脑。再加上编程有 Cursor 补，又是厂商在维护，不用我自己操心。

如果你有精力自己维护，也可以自己部署 Hermes Agent 或 OpenClaw。我以前就是这么做的，后来为什么放下了，第七章再讲。

### 3. 怎么开通

- 只是想体验：订 $30 一档的会员就够了。$8 的 Lite 不包含 Grok Bot。不同地区的价格不一样，下单前对比一下，以官方价格页为准；
- 本来就订了 X Premium+：现在 X 订阅都做整合了，可以直接关联到 Grok Bot，所以也不需要额外购买了；
- 想先免费试：Grok 新用户通过邀请链接注册，可以领 2 周的 Premium 免费试用。要注意三点：开始试用要绑信用卡；中国大陆不在活动范围内；按官方规则，被邀请的人转成付费以后，邀请人会得到一次额度重置。这个活动官方随时可能调整，以领取页面为准。

### 4. 五个词，用大白话讲清

刚打开 Grok Bot，最容易被几个词绕晕。先用大白话分清：

词

大白话

Bot

你雇的一个员工。有自己的人设、记忆和技能，一个账号可以雇好几个

云电脑

所有员工共用的一台办公电脑。它们在上面开浏览器、跑命令、存文件

连接器

发给员工的门禁卡，让它能进 X、Gmail、Notion 这些地方。在侧边栏的“连接应用”（英文界面叫 Connect apps）里管理，界面上分在“插件”一类，所以很多人也叫它插件

Skill

一本操作手册。一套固定流程写好一次，以后一句话就让它照着做

routine

闹钟。到点让它自动干活，比如每天早上出一份日报

### 5. 云电脑的三个脾气

这台云电脑有三个脾气，先记住：没人用的时候会休眠，可能被重置，所有 Bot 共用一台。

所以重要的数据，要存到它外面去；需要定时跑的任务，交给它自带的 routine。具体原因放在第六章第 4 节讲。

### 6. 背后是什么模型

官方没有说背后具体是哪一个模型。它是一个黑盒，按任务自动路由：可能路由到 Claude 的模型，也可能路由到 Grok 自家的模型。

网上有不少人用模型指纹工具去测，我自己也测过。但测出来的结果只能说明那一次请求，换个任务、换个时间，路由可能就不一样了。所以别纠结它背后到底是谁，看它把活干得怎么样就行。

### 7. 读完以后的完成标准

- 开通 Grok Bot，接上 X，能用一条只读指令读回正确的数据；
- 知道去哪找现成的 Bot，装之前会看它要哪些权限；
- 会给它做一次记忆大扫除，知道重要的数据要备份到哪里；
- 额度掉得快的时候，知道先查哪几处。

## 二、第一件事：接上 X，跑通一个只读任务

### 1. 为什么第一步是只读任务

刚开始，不用急着建一整支 Bot 队伍。先让一个 Bot 跑通一项真实的任务，更容易发现问题。这篇就从一个帮你运营 X 的 Bot 开始，后面每一章都接着用它。

第一次连接外部服务，先给只读任务。搜索帖子、读时间线、看账号资料都适合拿来测试；发帖、删除、关注、付费调用，等连接稳定了再开。

还有一点，插件卡片上显示“已安装”，界面上显示“Connected”，都不算数。我 9 月第一次接 X 的时候就遇到过：插件装上了，Bot 照样读不到账号。能进入真实的工具，并拿回正确的结果，这个 Bot 才算真正能用。

### 2. 三步接上 X

9 月那篇的第四到第六章，讲的是开 X Developer Account、建 Default Project、在项目里建 App。现在这一大段都可以跳过了。最新的 X 连接器，不需要开发者账号，在 Grok Bot 里用 X 账号登录授权就能用。

- 建一个 Bot：名字和职责写清楚，比如“X 运营助理，负责读数据、找选题、做复盘”；
- 授权 X：打开侧边栏的连接应用，① 在搜索框里输入 X，② 点开“插件”里的 X，用你的 X 账号登录授权；
- 跑验收指令：见下一节。
[/xiaomovps/article/2115738442181333337/media/2115737473263484928](/xiaomovps/article/2115738442181333337/media/2115737473263484928)

授权完成后，点开 X 插件：① 账户一栏显示“已连接”；② 工具一栏能看到启用了多少个工具，我这里是 99 个全开。

[/xiaomovps/article/2115738442181333337/media/2115737473225781248](/xiaomovps/article/2115738442181333337/media/2115737473225781248)

这里说的“X 的额度”，指的是 X 那边的 API 额度，和 Grok Bot 自己的周额度是两回事。现在只有发布帖子的时候，才会用到 X 的额度。接上以后，下面这些都不用花：

- 读自己账号的时间线、提及、点赞、收藏和关注；
- 搜全站的帖子、趋势和新闻；
- 读私信，汇总未读；
- 管理 List；
- 起草 X 文章，只存草稿，不会直接发；
- 安排通话和预约直播。

9 月那篇里还有一处要更新：那篇教大家给云电脑接 Cloudflare WARP 换出口。如果默认出口用着没问题，没必要为了换而换，网络改动越少，云电脑越稳定。

### 3. 一条可以直接复制的验收指令

接上 X 以后，先给它这一条：

> 只读取我的 X 账号，不要发布、删除、关注或修改任何内容。请返回账号名称、最新三条原创帖的发布时间、链接和当前互动数据。如果帖子引用了其他内容，把引用关系单独列出。执行前说明会调用哪些能力，预计成本较高时先暂停并询问我。

拿到结果以后，自己去 X 上打开最新那条帖子，核对一遍链接、时间和互动数字。都能对上，再让它做更长的搜索和自动整理。

我第一次跑这条指令的时候，它不光读出了我当天 22 点发的帖子和互动数，还顺着引用关系找到了我前一天的帖子，又问我要不要做一份账号日报。那一刻我才觉得，这东西是真的能干活。

到这里，你的 Bot 已经能读到真实的 X 数据了。下一步，别急着自己写提示词，先看看别人已经做好了什么。

## 三、第二件事：用现成的，别从零写

### 1. 为什么先用现成的

我刚开始也是自己从零写提示词，越写越长，越写越乱。后来去翻了一圈才发现，官方案例库已经整理了 56 个应用场景，社区网站上还有几百个别人分享的模板。你想让它干的事，大部分已经有人做过了。

从改别人的模板开始，比从零写快得多，也更容易看出好的提示词长什么样。

### 2. 去哪找：5 个网站

先去官方模板市场找，再去社区网站搜同类，最后看别人的提示词怎么写：

- Grok Bot Index（grokbotindex.com）：称收录了 487 个模板；
- Grokdex（grokdex.net）：社区排行榜，能看到大家都在用什么；
- AI Agents Grok Bot Hub（aiagents.org/grok-bots）：列了 273 个 Bot 和 19 个插件；
- GitHub 上的 awesome-grok-bot：收集提示词和配置。

### 5. 装之前，先看一眼权限

社区模板质量参差不齐。而且所有 Bot 共用一台云电脑，浏览器登录状态和凭据也是共享的：你装的任何一个模板，理论上都能碰到其他 Bot 能碰到的东西。

所以装之前先看一眼它要哪些权限。要发帖、要删除、要付费调用、要读密码的模板，先别急着装，至少别装在接了密码库的账号上。

前两件事做完，这个 Bot 已经能替你干活了。接下来按你想让它干什么，挑场景看。

## 四、日常怎么用：4 个场景

每一节都按同一个顺序写：什么情况下需要，怎么做，要注意什么，最后是我自己的选择。

### 1. 想运营 X

什么情况下需要：你在运营 X 账号，每天要刷提及、找选题、看数据。

怎么做：把前面那个 Bot 当成你自己的 X 信息站。

- 每天固定看一遍自己账号的提及，筛出需要回复的问题；
- 跟踪几个关键词，整理当天讨论量高的帖子和主要观点；
- 做复盘的时候，让它读取一段时间内的原创帖，对比浏览、点赞、评论和引用，找出表现明显不同的内容；
- 配一个爆款监控的 Skill，再设一个 routine，让它每天定时把同领域的热帖整理成日报发给你。

要注意什么：X 搜索有频率和条数限制：每分钟 30 次，每天 1,000 次，每次 25 条，按固定窗口计算。这是我自己查、加上在群里问来的，不是官方公布的数字，只当参考。另外，它给的摘要可能漏掉语境，选题时让它收集材料，最后的判断还是要回到原帖。

我自己的选择：搜 X 是我离不开 Grok Bot 的第一个原因，现在基本不用自己去刷 X 了，有爆帖它会第一时间告诉我。

### 2. 想在手机上交代事

什么情况下需要：你希望不开电脑，在手机上就能把事情交代下去。

怎么做：10 月 22 日的更新以后，Grok Bot 的手机 APP 可以调用手机上的几个系统应用。打开 APP 里的连接应用，选 iPhone 这一栏，我 10 月 29 日截图时列了 6 项：日历、家庭、提醒、通讯录、位置、闹钟。每一项要单独点允许，不会一次性全部打开。需要最新版的 APP，以及支持 Grok Bot 的订阅。

我用下来最实用的是 ① 日历和 ② 提醒：跟它说一句“明天下午三点提醒我开会”，到时间手机就会弹系统通知。

不想单独开 APP 的话，在 X 的私信（X Chat）和 Slack 里也能直接找到你的 Bot。

[/xiaomovps/article/2115738442181333337/media/2115737474882547713](/xiaomovps/article/2115738442181333337/media/2115737474882547713)

要注意什么：刚推送时，权限页里还有一项“信息”（读写短信），我截图时这一栏里已经看不到了。别指望它替你收发短信和 iMessage，能用什么，以你自己 APP 里实际列出的为准。

我自己的选择：用到这一步，我才觉得直接用大厂的集成方案更省时间。

### 3. 想管邮箱和密码

什么情况下需要：你有好几个邮箱，每天光是翻邮件就要花不少时间；或者经常要登录各种网站。

怎么做：

- 邮箱：把 QQ、Outlook、163 这些邮箱统一转发到一个 Google 主邮箱，按来源打标签，让 Grok Bot 定时扫描、整理摘要；需要回复的，让它先起草，自己检查过再发。Grok Bot 现在也能直接领一个自己的专属邮箱地址，适合拿来注册测试账号；
- 密码：自建 Bitwarden 或者用官方免费版，在 Grok Bot 的云电脑里装 Bitwarden 的命令行工具 bw，配好访问凭据，让它按需读密码。我用下来比 1Password 顺手。

要注意什么：给它的凭据，权限越小越好，主密码和恢复密钥永远不要交给它。还是那句话，所有 Bot 共用一台电脑：给 Bot 用的密码，最好单独建一个库，只放测试账号这类低风险的密码；接了密码库的账号，不要装来路不明的社区模板。

我自己的选择：邮箱和密码都接进了我自己的工作流，现在一句话就能让它把后面的事办完。

### 4. 想做图片和视频

什么情况下需要：你要做封面、配图，或者想把文章变成视频。

怎么做：

- 生图：我把用 Grok 图片模型做简易封面的步骤封装成了一个 Skill，每次一句话出图；
- 视频：社区里有 3 个我觉得值得试的视频 Bot。Grok Bot Video Studio 做文生视频，有多镜头分镜和字幕；Grok Studio 把文章、PDF、网页转成带 AI 主持人的讲解视频；Video Editor 做口播素材的自动剪辑、字幕和 B-roll（插在口播中间的辅助画面），底层用的是 FFmpeg、Whisper 和 Remotion。

比如下面这张，是我让图片视频小助手给 DeepSeek Harness 那篇长文做封面，① 一次出四种风格，挑一张再细调。

我自己的选择：日常的封面和配图，完全够用。

## 五、拿它写代码

这一章适合会写代码的读者，不写代码可以直接跳到第六章。

### 1. Grok Bot 加 Cursor：出门只带手机

什么情况下需要：你想在手机上把开发任务交代出去，回到电脑前只负责验收。

先准备好三样：一个支持 Grok Bot 的订阅，一个 GitHub 账号，一个 Cursor 账号。

怎么做：

- 准备：同一个账号关联 Grok Bot 和 Cursor，两边都连上 GitHub 仓库；
- 下发：在手机上把任务交给 Grok Bot，它再派给 Cursor Cloud；
- 开发和测试：Cursor Cloud 在云端写代码、跑测试，用截图和录屏回传结果；
- 合并和发布：走 GitHub PR（合并代码前的审查请求），CI/CD（自动测试和部署）兜底。

整个流程里，我只做三件事：提任务，看结果、合 PR，确认发布。比如下面这次，① 我在手机上说一句“提一个测试 PR，走一下 Cursor 流程”，② 它派给云端 agent 开好 PR，自己核对完改动，再等我确认要不要合并。

[/xiaomovps/article/2115738442181333337/media/2115737475603980288](/xiaomovps/article/2115738442181333337/media/2115737475603980288)

要注意什么：上线前，代码和权限还是要自己查一遍。AI 写的代码，最后签字的是你。

### 2. Claude Code 指挥，Grok Bot 干活

什么情况下需要：你平时主力用 Claude Code 或 Codex，想把一部分活分出去。

怎么做：Grok Bot 的账号本身就挂在 Cursor 账号上，关联订阅时也要先用 Cursor 账号登录。所以用 cursor-grokbot-agents 这个扩展，就能让 Agent SDK 通过你的 Cursor 账号调用 Grok Bot，并且保留它原有的对话、记忆和工具。三步：

- 让 Claude Code 或 Codex 自己装上这个扩展；
- 打开 Grok Bot 授权；
- 启动连接，绑定你要用的那个 Bot。

接好以后的分工是：Claude Code 拆任务，Grok Bot 改代码、提 PR，Cursor Cloud 跑测试，最后回到 Claude Code 验收。主 Agent 换成 Codex 也一样。

要注意什么：生产环境的代码，照样要自己把关。

### 3. DeepSeek Harness 那条还在折腾

社区里已经有几个让 DeepSeek Harness 和 Grok Bot 互相派活的项目，但都不是直接对接，要靠 webhook 之类的方式中转。我打算自己写一个插件，写好了再单独分享。

我自己的选择：写代码这块，我现在的主线是 Grok Bot 加 Cursor，Claude Code 当总指挥。

## 六、第三件事，以及怎么用稳

### 1. 记忆大扫除（第三件事）

为什么会越用越笨：用久了，记忆、人设和 Skills 里的内容越堆越多，开始出现重复和互相冲突的指令。它不知道该听哪一条，表现就越来越差。还有一个原因我只能猜：模型路由是黑盒，简单任务可能被分到了更轻量的模型。

这个问题我在用 Hermes 的时候就遇到过。而且 Grok Bot 的记忆没办法精确删除，我试过直接让它删掉某几条记忆、重新整理，有些就是做不到。能做的，是隔一段时间用提示词让它自己优化一遍，尤其是 Skill 和记忆。所以我的建议是：每半个月，给它做一次记忆大扫除。

怎么做，按这四步来：

- 先让 AI 找问题，再决定怎么改。别一上来就删，让它先列出哪些规则重复了、哪些互相冲突、哪些已经过期；
- 清理过期的记忆和规则。以前的项目、已经不用的工具，相关的记忆都可以清掉；
- 一条规则只在一个地方维护。长期偏好留在记忆里，具体流程放进 Skill。同一条规则在两个地方都写了，迟早会冲突；
- 改完让 AI 自检，并且先备份。改之前留一份，改完对比差异，确认没删错东西。

我自己实际用的是下面这条，分两步，可以直接复制：

> 第一步（只查不改）：

> 扫描一下你自己的长期记忆、上下文设定和所有 Skill，找出下面四类问题，先出清单，这一步不要改任何东西：

> 1. 冲突：新旧规则互相矛盾，或者同一件事在两个地方写法不一样

> 2. 重复：意思相同、可以合并成一条的内容

> 3. 过时：已经被新决定取代，或者指向已经不存在的文件、章节、工具的内容

> 4. 和数据对不上：记录里的结论，和我最近实际的数据或做法不一致

> 每一条都写清楚：出处、问题是什么、你建议怎么处理。

> 第二步（分两类处理）：

> - 明显过时、或者新旧规则里能确定以新的为准的，你直接改，改完告诉我改了什么

> - 需要我做取舍的，不要替我选，列出选项等我拍板

> - 改 Skill 和记忆时，只改有问题的那一行，不要重写整份

> - 删不掉的条目，不要硬删，写一条更新后的新条目覆盖，并告诉我哪些没删掉

> - 不要碰任何密钥、账号和凭据

最后那句“删不掉的条目写新条目覆盖”，就是针对记忆没法精确删除这一点。

我拿调研助手跑了一遍：① 是我发的指令，② 它先只读不改，查了六个 Skill 和 84 条记忆，出了一份问题清单。

[/xiaomovps/article/2115738442181333337/media/2115737475616563200](/xiaomovps/article/2115738442181333337/media/2115737475616563200)

第二步，① 需要我拍板的，它列成 A、B、C 选项；② 我只回了一句话；③ 它按我的选择改完，每处只动了有问题的那一行。

[/xiaomovps/article/2115738442181333337/media/2115737475775934464](/xiaomovps/article/2115738442181333337/media/2115737475775934464)

要注意什么：知识库里的客观事实，最好自己整理，不要全交给它。

说到底，AI 用久了会乱，是因为没人管它。人要当 AI 的指挥官。

### 2. 定时备份

我第一次意识到要备份，是在查 Grok Bot 内容的时候，发现有一部分不见了。翻日志才知道，中间云电脑被重置过一次。

后来又遇到一次：云电脑回滚，我自己点了 Reset，恢复到前一天下午三点的备份，结果丢了一个 Skill 的修改。官方的说明里也写了，重置时如果云电脑连不上，最近的改动可能会丢。

所以重要的东西，一定要存到它外面去：

- 让它每天同步一份到 GitHub 私有仓库，可以参考这条：

> 每天凌晨 3 点，把所有 Bot 的 Skill、人设、记忆和工作目录里的文本文件，同步到我的 GitHub 私有仓库。不要提交任何密码、Token 或 API Key，提交前先扫一遍敏感信息。第一次执行前，先列出要备份的清单，等我确认。

我自己的备份仓库长这样：① 每天凌晨 3 点多自动提交一次；② README 里写明只放文本和配置，不放令牌、密钥和登录状态，提交前自动扫描。

[/xiaomovps/article/2115738442181333337/media/2115737476031811584](/xiaomovps/article/2115738442181333337/media/2115737476031811584)

- 想省事，也可以用现成的模板：官方模板市场里有一个 Backup 模板，能定时把各个 Bot 的设置和重要文件备份到 GitHub 私有仓库和 Google Drive。要注意，它是第三方用户做的，不是官方出品，装之前同样先看权限；
- 不要提交密钥：备份仓库就算是私有的，也不要把密码和 API Key 放进去。

### 3. 额度

先分清两种额度：一种是 Grok Bot 自己的周额度，每周重置，干活都在花它；另一种是第二章说的 X 的额度，现在只有发帖才用。下面说的都是前一种。

额度掉得快，通常是这三个地方：

- routine：定时任务每跑一次都在花额度，频率设得太高很容易烧光；
- Bot 之间互发消息和群聊：群里每条回复、Bot 之间的每条消息都算用量。两个 Bot 能干完的活，拉一个六个 Bot 的群，只会多花钱；
- 大任务：开工前先把范围定小，让它预估一下要花多少。

另外，周额度用完以后，如果开了按需付费，会接着扣钱。不想超支，就在 Grok Bot 的设置 → Usage & Billing 里，把按需用量的月度上限设成 0；用 X 订阅的，在额外用量（Additional usage credits）里设。要注意，上限挡不住已经在跑的任务，可能会略微超出一点。

进阶：$30 一档额度不够怎么办。我的办法是在云电脑里装 Pi，接 OpenRouter 的免费模型，让 Grok Bot 把简单的任务分流给 Pi。OpenRouter 充 $10 以后，免费模型的调用次数会从每天 50 次提到 1,000 次，每分钟 20 次。要注意，这不是无限 Token，而且 Grok Bot 调度本身也要花额度。

### 4. 多个 Bot 和定时任务

第一章说云电脑有三个脾气，具体是这样的：

- 没人用的时候会休眠。你自己在里面配的 cron（Linux 自带的定时任务）和后台进程，休眠期间会暂停；
- 所有 Bot 共用一台电脑。浏览器登录状态、文件和命令行凭据都是共享的。官方文档的说法是，各个 Bot 的屏幕只是不同的工作面，不是不同的安全边界；
- 重建以后，不是什么都还在。文件和登录状态一般能恢复，但你自己装的软件不一定会保留。

另外，它的 16G 内存在你不用的时候，会被收回去一部分，用的时候再还给你。所以别把它当成一台可以随便折腾的服务器。具体怎么做：

- 多个 Bot 共用一台电脑：给每个 Bot 分好目录，权限给到刚好够用就行；
- 定时任务可能延迟或漏跑：定期看一眼 Run History。真正重要的任务，用 VPS 或 GitHub Actions 再做一层独立的监控；
- 一个小技巧：Bot 建多了，默认头像都长得差不多。可以让它按每个 Bot 的职责生成一套头像，一眼就能分清谁是谁。

## 七、我现在怎么用

这一个月，我做了一个比较大的调整：把自己维护了很久的 Hermes Agent 放下了，主力换成了 Grok Bot。

为什么放下 Hermes。 中间其实有不少沉没成本：三层处理、上下文压缩、智能路由，还要跟着 GPT 换模型不停地维护。Grok Bot 是厂商在维护，比 Muse 开放，社区也有项目能接微信。Hermes 是白盒，什么都要自己管；Grok Bot 是黑盒，不用我维护。

订阅也跟着精简了。 现在每个月 $120：Claude Pro $20，加 Grok Bot $100。GPT 的 $100 订阅和单独的 X Premium+ 都取消了。$100 这一档，我每周最多用到 70% 左右，日常完全够用。

原来靠 GPT 做的事，现在都交给 Grok Bot。 生图用 Grok 的图片模型，封装成 Skill，一句话出封面；视频交给第四章那几个视频 Bot；Computer Use 用第三方浏览器加 MCP 或 Skill，反正 Grok Bot 本身就是一台高配的云电脑。

代价也有：Computer Use 没有以前那么灵活，图片和视频生成算是够用。换来的是 X 数据收集、Grok Bot 配 Cursor 写代码、手机端这几块，全都补上了。

Grok Bot 也不是什么都好，数据会重置，路由是黑盒。数据的问题靠备份补，路由没法控制，就把活拆小、把结果核实。AI 没有对错，只看需求。
